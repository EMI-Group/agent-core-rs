# tests/ — runner integration suites

## Intent

Behaviour-level tests for the crate's public seams: the registries and their sub-managers, the callback framework with its filters/chains/combinators, the guardrail binding, the in-process queue, the run monitor, the HITL hub, the team runtime pool, every spawn backend and the spawn seam's health/snapshot/cancel accessors, the runner's spawn routing and spawn observability, the runner lifecycle, and the three execution paths (agent, workflow, team) with their streaming variants.
Every suite is offline and deterministic and drives only the public API, exactly as `openjiuwen-harness` and `openjiuwen-cli` will.

## API Surface

Suites (one file per area):
- `resources.rs` — register/get/remove/list/clear for tools/agents/workflows/teams; duplicate policies (`Fail`/`Keep`/`Replace`); card and name lookups; provider-per-get semantics; revision counters; `release`; concurrent registration; card JSON round-trip.
- `managers.rs` — the sub-managers over the four registries: the tag facade (`TagMgr`, `GLOBAL_TAG`, match/update strategies), the model factory registry, prompt templates, system operations, and the cross-manager wiring (`is_pristine`, `release`, the `Debug` dump).
- `managers_mcp.rs` — the MCP-server manager over local `McpConnector` fakes: registration, connection state, tool loading/publication, failure surfacing, disconnect/remove teardown, the per-server async lock, the serde state shape, and the typed error from the default connector.
- `callbacks.rs` — event-name mapping over `CallbackEvent::ALL`; priority ordering (descending, insertion tiebreak); sync and async handlers; error isolation (`Err` recorded, later handlers still run); `Abort` and `Stop` verdicts; `once`; enable/disable; unregister by id/event/namespace/tag; no-subscriber fast path; per-event isolation.
- `callback_chains.rs` — `CallbackChain` dispatch order, verdicts, per-entry filters, nesting, and mutation (append/prepend/remove/clear/names).
- `callback_decorators.rs` — the decorator equivalents: the `on` builder (`HandlerBuilder`/`BuiltHandler`), `emit_before`/`emit_after`/`emit_around`, `transform_io` as both an `EventFilter` and a `CallbackHandler`, and the `wrap` layer stack with `WrapRegistry`.
- `callback_filters.rs` — every built-in filter (`NameFilter`, `KindFilter`, `SessionFilter`, `RateLimitFilter`, `CircuitBreakerFilter`, `ValidationFilter`, `LoggingFilter`, `AuthFilter`, `ParamModifyFilter`, `ConditionalFilter`, `PredicateFilter`), the `and`/`or`/`not`/`lenient` composition operators, the filter run loop, and one end-to-end gate over a `CallbackChain`; time-dependent filters are driven by `ManualClock`.
- `security_binding.rs` — `bind_guardrails` registering four stages at priority 100 in namespace `guardrail`; a blocking prompt-injection finding on `LlmInvokeInput` aborting `trigger` with `Error::Security`; a non-blocking finding left in the report; `scan_stage_for`/`event_for_stage` round-trip; `Runner::scan` returning the pipeline outcome and its "no pipeline" error.
- `message_queue.rs` — publish/request happy paths; per-topic FIFO ordering; a request on an unsubscribed topic (`NotFound`) and one with no handler; handler errors returned to the requester; request timeout (`Timeout`) with the handler still running; publish before `start` (`Config`); start/stop idempotence; `unsubscribe` joining the worker; `create_message_queue` unsupported backends.
- `monitor.rs` — `RunMonitor` transition sequences, `list_active` ordering, retention bounds (`EVENT_HISTORY_LIMIT`/`LIVE_RUN_LIMIT`), typed error paths, the broadcast stream (including `Lagged`), and the JSON shape of a status and an event.
- `hitl.rs` — the `InteractionHub` live-run registry, inbox delivery (`DeliverResult`), pause/resume/cancel signals, real interaction round trips through a session, and the run-path seam that registers and finalises a run.
- `spawn_subprocess.rs` — the subprocess backend over real stdio pipes: the "child" is this same test binary re-executed through an `#[ignore]`d libtest case, so echo, streaming, crash, silence, malformed and oversized framing, health failure, and graceful-to-force shutdown are covered without a second fixture.
- `spawn_remote.rs` — the HTTP remote client against a loopback `wiremock` server: invoke/stream/cancel wire, error mapping, the deferred `Mq`/`A2a` variants, and the `RemoteSpawner` adapter.
- `spawn_seam.rs` — the seam's health, snapshot, and cancellation accessors driven exclusively through `Arc<dyn SpawnedAgent>`: subprocess (`backend`, `pid`, `is_healthy`, `health`, snapshot agreement, `cancel_task` as typed `Unsupported` naming `subprocess`, graceful `shutdown`, then dead); subprocess `health_fail` mode (`health` returns `Ok(false)` and `is_healthy` follows while the child stays alive); external command (a resolved program launches through the seam and its handle reports `backend`/snapshot backend `external_command`, a missing command is `NotFound` naming it and starts nothing); in-process (`from_handler` and factory forms, `pid` always `None`, `health` = liveness, `send`/`stream` reach the handler, shutdown/force_kill idempotent); remote (health `false` before and `true` after a request, `cancel_task` hitting `/agents/{id}/cancel`, snapshot backend `remote_http`, `pid` `None`); and the defaulted seam methods of a minimal local handle (`backend` `Unknown`, `is_healthy` = `is_alive`, `health`/`cancel_task` `Unsupported`), plus `SpawnHealth`'s snake_case JSON and tolerance of unknown fields.
- `spawn_routing.rs` — the runner's spawn facade: `spawner`/`spawn_backend`/`spawn_backends` before and after `set_spawner`, a registry's sorted backends beside the still-installed single spawner, `set_spawner` clearing the registry; a spec's backend hint routing to the real in-process backend while a counted fake sibling is untouched; a second runner with only a single spawner never consulting the other's registry; a successful spawn in `active_spawns()` (`RunKind::Spawn`, session, backend detail) with shutdown and drop each removing it and the monitor recording the terminal outcome; a failed spawn adding nothing; `spawn_agent_with(RemoteMq)` as `Unsupported` naming Pulsar; `spawn_agent_with` without a registry as `Config` naming `Runner::set_spawner_registry`.
- `runner_lifecycle.rs` — `new`/`with_config`/accessors; `start`/`stop` idempotence; start builds the checkpointer and starts the queue; stop releases the registries; `release(session_id)`; `Runner::global()` identity plus `reset_global()` isolation; execution before `start` still works locally (Python parity: runs do not require `start`).
- `runner_facade.rs` — the facade's own end-to-end suite for the agent execution accessors (`run_agent` and its streaming form) driven through the facade rather than through the `run` free functions, plus the security/spawner wiring on the instance; the facade's `run_workflow` path is covered only by `openjiuwen-e2e/tests/kernel_flow.rs::local_runner_runs_an_agent_and_a_workflow`.
- `run_agent.rs` — local `ScriptedAgent` through `AgentRef::Id` and `AgentRef::of`, plus one real `ReActAgent`+`ScriptedModel` run; owned session id from `conversation_id`, from `RunOptions::session_id`, and from `default_session_id`; caller session untouched (no commit); missing id (`NotFound`); callback order and priority; `Abort` from an input handler; timeout and cancellation (pre-cancelled and mid-run); streaming frame order, one `AgentStreamOutput` per frame with 0-based `index`, terminal-error behaviour, owned-session checkpoint written via `post_run`.
- `run_workflow.rs` — start→echo→end workflow through `WorkflowRef::Id` and instance with `${echo.query}` passthrough; `WorkflowInvokeInput`/`Output`; created vs caller session (the injected checkpointer proves the created backend and id); a failing component returning the error and firing `WorkflowError`; streaming frames plus `WorkflowStreamInput`/`Output`.
- `run_team.rs` — a real `BaseTeam` + handoff strategy over two closure members: `invoke_team` returns the final answer and tears the owned lease down (runtime unbinding asserted); streaming forwards strategy frames verbatim and tears down on completion; caller-provided session reused and left bound; missing id (`NotFound`).
- `team_pool.rs` — the pool's happy path over a real handoff team: frames, `wait`, the active listing, the busy rejection, the monitor walk, and the configuration wire shape.
- `team_pool_leases.rs` — lease refcounting, joining two acquisitions onto one entry, `PoolLease` keep-alive, and the reaper's idle/idle-eviction rules.
- `team_pool_lifecycle.rs` — admission beyond capacity (queueing until a permit frees), `pause`/`resume`, `stop`/`stop_all`, and the closed-pool rejection.
- `team_pool_hitl.rs` — a pooled run's inbound payload delivery, the payload buffer and its frame, the drain, and unbinding on finalisation.
- `api_surface.rs` — compile-time pinning of the crate-root surface: every re-export (dispatch core, chains, filters, handler combinators, monitor, HITL, pool, spawn backends, resource sub-managers), trait-object coercion (`AgentRef`/`WorkflowRef`/`TeamRef`/`MessageHandler`/`CallbackHandler`/`AgentSpawner`/`RemoteClient`/`McpConnector`), `Send + Sync` and serde checks, the deliberate module-only scoping of the free combinators, `RunOptions` builder reachability, `CallbackEvent::ALL` length/round-trip, and JSON round-trips (`SpawnMessage`'s `f64` timestamp compared with the documented tolerance, never exact equality).

## Constraints

- Only the public API of `openjiuwen-runner` (plus `openjiuwen-test-support`, `openjiuwen-agent`, `openjiuwen-session`, `openjiuwen-workflow`, `openjiuwen-multiagent`, `openjiuwen-security` for fixtures).
- No network, no sleeps for ordering, no wall-clock assertions; timeouts are short and prove a deadline only.
- `wiremock` is the only loopback server (used by `spawn_remote.rs` and `spawn_seam.rs`); the subprocess and external-command cases in `spawn_subprocess.rs` and `spawn_seam.rs` re-execute this test binary, never an external program.
- The fake-child bootstrap is duplicated per binary, never shared: the child is the binary's own `#[ignore]`d `fake_child` test selected with `fake_child --exact --ignored --test-threads=1 --nocapture`; `--nocapture` is mandatory (libtest would otherwise capture the protocol frames) and the child body must write a leading newline to close libtest's partial `test fake_child ... ` line before its first frame.
- The execution suites drive the `openjiuwen_runner::run` free functions over a `RunServices` fixture; only lifecycle/facade suites construct `Runner`, and never `Runner::global()` without `reset_global()`.
- Behavior ports cite the Python test file they mirror in a comment.
- `common/mod.rs` holds shared fixtures: `services()`, `services_with_checkpointer`, `services_with_default_session`, `services_with_checkpointer_and_default_session`, a local `ScriptedAgent` (delay/gate/failure/stream chunks/call counters) plus `scripted_agent(id, answer)` and `answer_frames()`, `EchoComponent`/`FailingComponent`, `passthrough_workflow(id)`/`failing_workflow(id)`, a real two-member handoff `BaseTeam` with a `TeamCalls` log (`handoff_team_fixture`, `team_calls`, `provider`), `RecordingSession`, `RecordingCheckpointer`, and the recording callback helpers (`recorder`, `record_at`, `record_all`, `recorded*`, `agent_events`, `workflow_events`).
- `common/mod.rs` is included per test binary with `mod common;`; it is private to this crate's test targets, so another crate (e.g. `openjiuwen-e2e`) cannot import it and must inline its own fakes or add its own `tests/common/mod.rs`.
- Facade coverage lives in `runner_lifecycle.rs` (lifecycle and `run_agent_through_the_facade_without_start`) and `runner_facade.rs` (the agent execution accessors); every other execution-path suite drives the `openjiuwen_runner::run` free functions over `RunServices`.
- No suite reads or mutates the process environment: there is no `TempHomeGuard`, `EnvGuard`, `#[serial]`, or env mutex here, and none is needed because the runner never reads `OPENJIUWEN_*`; `spawn_subprocess.rs` sets variables on the child `Command`, not in the parent.
- Tokio tests are plain `#[tokio::test]` (current-thread) except the two concurrency cases in `resources.rs`, which use `#[tokio::test(flavor = "multi_thread", worker_threads = 4)]`, and the pooled suites, where the current-thread runtime is what makes a freshly started run observe its first frames; waits are `Notify` handshakes or short `RunOptions::with_timeout` deadlines, never sleeps for ordering.

## Routing Table

- `./tests/common/mod.rs` → shared fixtures (scripted agents, workflow builder, handoff team, recording handler)
- `./tests/*.rs` → the suites listed above
- `../src/` → the implementation under test
