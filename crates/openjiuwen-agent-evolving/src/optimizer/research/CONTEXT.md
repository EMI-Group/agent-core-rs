# optimizer::research

## Intent
The research optimizers: textual-gradient search that turns evolution signals into updated operator text for instructions, tools, memory entries, skill experience, Metis context sections and TTSE tips.
Ports the portable core of Python `openjiuwen.agent_evolving.optimizer` (`base.py` plus the `llm_call`, `tool_call`, `memory_call`, `skill_call`, `context_evolve_call` and TTSE optimizers).

## API Surface
- `TextualParameter` — one named value (instruction, tool description, memory entry list, …) plus the textual gradient accumulated since the last accepted update and a `version` bumped by `set_value`/`apply_gradient`.
- `OperatorState` — the ordered parameter map of one operator (`new(operator_id, kind)`) tagged with `OperatorKind` (`instruction`, `tool`, `memory`, `skill`, `context`, `tip`); `with_parameter`, `parameter`/`parameter_mut`, `set_parameter`, `apply`, `state`/`restore`.
- `TextualStrategy` (trait) — the per-domain policy: which signals to consume, which parameter they update, the deterministic rewrite, and the model prompt.
- `TextualGradientOptimizer<S>` — the shared engine: `backward(&[EvolutionSignal])`, `propose(limit)`, `observe`, `best`, `operators_state`/`restore_state`, `history`, `signal_tracker`, `provenance`, `with_operator`, `with_model`, `with_max_proposals`, `with_request`, `with_policy`.
- `ProposalRecord`, `parse_tagged`, `IMPROVED_TAG`, `PARAMETER_SEPARATOR`, `CANDIDATE_META_KEY`, `DEFAULT_MAX_PROPOSALS` (8), `MAX_GRADIENT_CHARS` (2000).
- Strategies and their optimizers: `InstructionStrategy`/`InstructionOptimizer`, `ToolStrategy`/`ToolOptimizer`, `MemoryStrategy`/`MemoryOptimizer`, `SkillExperienceStrategy`/`SkillExperienceOptimizer`, `MetisStrategy`/`MetisOptimizer`, `TtseStrategy`/`TtseOptimizer`; `DEFAULT_SECTION_BUDGET` (8), `DEFAULT_TIP_CAPACITY` (12), `DEFAULT_CLUSTER_THRESHOLD` (0.5).

## Constraints
- Deterministic without a model: every rewrite appends, dedupes and bounds text in signal order, so identical signals give identical candidates.
- An injected `openjiuwen_core::foundation::llm::Model` only adds a model-driven proposal path; an unparseable answer or a provider error falls back to the deterministic rewrite and records the reason in the proposal provenance.
- Signal routing is by `EvolutionTarget` and `tool_name`, so one tool's feedback never leaks into another tool's description.
- Text stays bounded: `MAX_GRADIENT_CHARS` for accumulated gradients, the strategy's `max_chars`/`max_bullets` for instructions, and per-strategy capacities for memory entries, skill bullets and tips.
- Memory entries and skill bullets are JSON arrays of strings appended newest-last; eviction removes the lowest-weight item first, ties oldest first.

## Design Decisions
- One engine plus per-domain strategies replaces Python's per-optimizer class hierarchy; the wrapper types (`InstructionOptimizer`, …) are thin newtypes generated by a macro so each keeps a usable `new`/`with_*` surface.
- `backward` returns the number of signals it consumed, which makes routing assertions direct instead of inferred from state.
- Metis keeps a compact selection record (`{"sections", "dropped", "budget"}`) rather than the section text, so a context assembler consumes the plan and the text stays in the operator's other parameters.
- TTSE clusters signals by Jaccard similarity of normalised token sets and keeps one representative per cluster, so two runs over the same signals produce identical tips.
- The `<improved>` tag is a plain parsed marker (`parse_tagged`) instead of a structured model protocol, which keeps the model path testable with a scripted model.
