# openjiuwen-extensions

## Intent

Optional integrations and backend adapters that live outside the kernel: the A2A protocol client/server (JSON-RPC, SSE and REST bindings), OpenTelemetry tracing over the session `TraceSink` SPI with OTLP/HTTP export in both encodings (JSON and protobuf), the dependency-neutral observability utilities of Python's `observability/` package (semantic conventions, credential/error redaction, `@oj-seq` content addressing, tool/error classification, the collector-free OTLP-JSON file exporter and the export-time span projection wrapper), and config-driven adapters over the kernel's checkpointer, store, message-queue, and sys-operation seams.
Maps to the Python package `openjiuwen.extensions` (v0.1.20): `a2a/`, `tracer_otel/`, `observability/`, `checkpointer/`, `store/`, `message_queue/`, `sys_operation/`, `context_evolver/`, `vendor_specific/`.
Nothing in the kernel depends on this crate; every heavy dependency and external service sits behind a Cargo feature (or lazily activates only when a caller uses it), so the default build needs no network, no broker and no collector.

## API Surface

Every module is reachable from the crate root; feature-gated modules disappear entirely when their feature is off (no silent stubs), except `otel`, which keeps a documented no-op seam.

- `a2a` (`feature = "a2a"`) — `A2aClient`, `A2aRemoteClient`, `A2aServer`, `A2aServerAdapter`, wire types (`AgentCard`, `Message`, `Part`, `Task`, `TaskState`, …), JSON-RPC envelopes, `A2aTransformer`, `AgentCardAdapter`, `harness_bridge` (A2A ⇄ `openjiuwen_harness_protocol`), and the REST `HTTP+JSON` binding (`A2aTransport::{JsonRpc, Rest, Both}`, `rest_path`/`rest_prefix`, REST routes under `/a2a/rest`, `{"error":{code,status,message}}` envelope).
- `otel` (always compiled) — `OtelTracerConfig` (plus `from_env`/`apply_env`), `semconv` constants, `truncate`/`hash_value`/`Redactor`, span-name builders, and `init_otel_tracer` → `TracerHandle`; with `feature = "otel"` the handle is a real SDK provider with batch export plus `OtelTraceSink`, `OtelAgentHandler`, `OtelWorkflowHandler`, and a `tracing-opentelemetry` layer.
- `otel::otlp` (`feature = "otel"`) — `OtlpHttpExporter` (OTLP/HTTP `POST {endpoint}/v1/traces` on an exporter-owned thread, fail-open, idempotent `shutdown_with_timeout`) in either `OtlpEncoding`: JSON (default, `new`) or the hand-written protobuf encoder (`with_encoding`); plus the `OPENJIUWEN_OTEL_*` / standard `OTEL_*` endpoint-header-protocol resolvers (`http` = JSON, `http/protobuf` = protobuf).
- `otel::grafana` (`feature = "otel"`) — `GrafanaCloudConfig` OTLP gateway preset (`Authorization: Basic`) and `GrafanaAgentConfig`, the self-hosted Agent/Alloy preset that pushes to an already-running local collector (`DEFAULT_LOCAL_OTLP_ENDPOINT`, default `http://localhost:4318`, optional headers); starting or discovering a collector stays a host concern.
- `otel::langfuse` (`feature = "otel"`) — the OTLP preset (`{host}/api/public/otel` + Basic auth) and `LangfuseClient` REST ingestion (`POST /api/public/ingestion`, typed `trace-create`/`span-create`/`generation-create` events, batched).
- `observability` — dependency-neutral observability utilities (always compiled, `otel`-gated parts marked): `project_semconv` (project `agentteam.*`/`deepagent.*`/`openjiuwen.*` namespaces, trajectory key sets and versions, pinned `GenAI` registry metadata), `redaction` (credential masking, error summary/stack-trace redaction), `content_addressing` (`@oj-seq` prefix chains, OTLP JSON attribute addressing), `tool_outcome` (tool-failure classification), `error_reporting` (`error_reason`), `deferred` (typed `Unsupported` seams for the SDK-only Python modules), plus `file_exporter` (`TraceFileExporter`, the WAL behind `ExporterType::File`) and `transforming` (`SpanTransform`, `TransformingSpanExporter`) under `otel`.
- `checkpointer` — `build_checkpointer(&CheckpointerConfig)` dispatching to the kernel backends, and with `feature = "redis"` the live `RedisCheckpointer` (`RedisCheckpointerConfig`, `RedisConnectionConfig`, `RedisTTLConfig`, `RedisCheckpointer::{new, connect, create}`) over the in-crate RESP client; TLS and cluster slot routing stay `Error::Unsupported`.
- `redis` (`feature = "redis"`) — the in-crate RESP2/RESP3 client (`Client`, `ConnectionOptions`, `Reply`, `codec::{encode_command, parse_reply}`, `testsupport` fakes) over `tokio::net::TcpStream`.
- `store` — `StoreBackend` + `build_kv_store`/`build_document_store`/`build_vector_store` over `openjiuwen_foundation::store`: live single-node `RedisStore` plus `RedisDocumentStore`/`RedisVectorStore` (feature `redis`, brute-force client-side ranking), the live REST `ElasticsearchVectorStore` (k-NN search, `_meta` schema round-trip) and the kernel's live `ElasticsearchDocumentStore` wired through the factory (credentials from the URL userinfo or `username`/`password`/`api_key`); the Gauss/PostgreSQL document store is absent.
- `message_queue` — `QueueConfig` + `create_queue` over `openjiuwen_runner::mq`, the JSON `QueueBridge`, and with `feature = "pulsar"` the `PulsarConfig`/`PulsarMessageQueue` surface, which validates and then returns `Error::Unsupported` naming the missing protobuf-framed transport.
- `sys_operation` — `SandboxProviderSet` registration against `openjiuwen_sysop::sandbox::provider::SandboxProviderRegistry` (`register`, `register_gateway_provider`, `register_deferred` compatibility no-op) plus the three real remote providers in `sys_operation::remote`: `aio` (kernel gateway envelope), `jiuwenbox` (native `/api/v1` REST) and `yuanrong` (ADX), installed with `register_remote_providers`/`register_remote` and described by `REMOTE_SANDBOX_TYPES`; `shutdown_remote`/`shutdown_remote_all` take a `SandboxSelector` and return `TeardownReport`s (JiuwenBox `DELETE /api/v1/sandboxes/{id}`, YuanRong ADX environment delete, AIO typed `Unsupported` because its gateway exposes no delete API), and remote writes honour `create_if_absent` / `expected_content_sha256` with `supports_conditional_write()` reporting the backend's own capability.
- `context_evolver` — schemas and records (`Algo`, `normalize_algo_name`, `AddMemoryRequest`, `MemoryRecord`), per-family prompts and reply parsers, `MemoryStore` persistence (`InMemory`, `JsonFile`), the `VectorIndex` seam with `MemoryVectorStore` (in-process cosine) and `KernelVectorIndex` (any kernel `VectorStore` collection), the `TaskMemoryService` trait with two services: `DeterministicTaskMemoryService` (offline lexical + embedding scoring, optionally store-backed through `with_vector_store`) and `LlmTaskMemoryService` (model-driven over an injected `MemoryCompletion`, with `OpenAiChatCompletion`), built through `create_task_memory_service`/`create_task_memory_service_with_vector_store` and the serde `VectorBackend` selector, plus the documented `UnsupportedTaskMemoryService` opt-out.
- `vendor_specific` — deprecated `AliyunReranker` alias with the live DashScope HTTP rerank transport (`from_config`: `POST {api_base}/services/rerank/text-rerank/text-rerank`, `Bearer` auth, score mapping) and an adapter over an injected `openjiuwen_retrieval::Reranker` (`new`).

## Feature Matrix

| Feature | Default | Enables | External requirement | Behavior when off |
|---|---|---|---|---|
| — (default) | yes | `otel` seam (no-op), `observability` (semconv, redaction, content addressing, tool/error classification), `checkpointer`, `store` (memory/file, live Elasticsearch document + vector), `message_queue` (in-process), `sys_operation` (live `aio`/`jiuwenbox`/`yuanrong` transports), `context_evolver`, `vendor_specific` | none until a remote backend/collector is actually used | n/a |
| `a2a` | no | `axum`, `async-stream`, `bytes`; whole `a2a` module | none (client/server tests use loopback) | module absent |
| `otel` | no | `opentelemetry`, `opentelemetry_sdk`, `tracing-opentelemetry`, `tracing-subscriber`, `chrono`; real provider, OTLP/HTTP exporter (JSON and hand-written protobuf), the collector-free OTLP-JSON file exporter (`ExporterType::File`), Grafana Cloud/local and Langfuse presets, sink, handlers, tracing layer, `observability::{file_exporter, transforming}` | an OTLP/HTTP collector only for `ExporterType::Otlp`, in whichever encoding the protocol selects; `File` writes to `traces_dir` and Memory/Console/None need nothing | `init_otel_tracer` returns an inactive `TracerHandle`; `TracerHandle::is_active() == false`; `observability::{file_exporter, transforming}` absent |
| `sqlite` | no | `sqlx`, `openjiuwen-foundation/sqlite`, `openjiuwen-session/sqlite` | a local file/in-memory database | `sqlite` backends answer `Error::Unsupported` |
| `redis` | no | the `redis` client module, `checkpointer::redis`, `store::redis` (key-value, document and vector stores) | a Redis server for live use (tests use an in-process RESP fake) | module absent |
| `pulsar` | no | `message_queue::pulsar` surface | a Pulsar broker (not implemented) | variant absent |
| `mcp` | no | `rmcp` and `tokio-stream` dependencies only; MCP support itself is `openjiuwen_foundation::tool::mcp` (enabled by default in the kernel) | none | no module in this crate is gated on it |
| `live-tests` | no | network/service-gated tests | live services | those tests do not exist |

Remaining gaps (`Error::Unsupported` or documented behavioural limits, never silent degradation): OTLP/gRPC framing (no `tonic`/`prost` offline; both OTLP/HTTP encodings work), `rediss://` TLS and Redis cluster slot routing, the Gauss/PostgreSQL document store, the Pulsar and ZeroMQ message transports, AIO container teardown (its gateway exposes no delete API, so the idle reaper owns the lifecycle), cross-process conditional-write atomicity (the per-path lock is process-local and the final container write is not atomic against a foreign reader), Redis vector ranking (brute force, no RediSearch) and the Redis document/vector stores assuming one writer per collection, Milvus-backed `context_evolver` scoring (the kernel `VectorStore` seam is the integration point; no vendor Milvus client), and Elasticsearch credentials on the vector adapter (the new factory credential fields drive the document store only).
Python's `observability/` SDK-adapter layer is deferred but typed, never silent: `setup.py`/`demand.py`/`runtime.py` (one process-global provider with reference-counted acquire/release — this crate keeps one `TracerHandle` per ownership scope), `span_record_processor.py`/`trajectory_events.py`/`span_context.py` (async span-record and stream-frame fan-out plus the contextvar span tracker, which need a trajectory data plane and frozen `ReadableSpan`s), `instrumentation.py` (monkey-patched HTTP/FastAPI instrumentation, no Rust hook surface) and `context_compression_handler.py` (compaction → trajectory event bridge) all answer `ErrorKind::Unsupported` through `observability::deferred`, whose `*_DEFERRED_REASON` strings name the missing capability and the supported alternative.

## Constraints

- Only this crate and its `Cargo.toml` change from here; kernel crates are consumed as re-exported through `openjiuwen-core` (`session`, `runner`, `sys_operation`, `retrieval`, `foundation`).
- Async-first: tokio I/O, no blocking calls on async tasks, public streams are `BoxStream<'static, Result<T>>`, cancellation via `tokio_util::sync::CancellationToken`.
- The only sanctioned blocking seam is the OTLP exporter thread: `BatchSpanProcessor` drives `export()` on a plain std thread, so the exporter owns a current-thread runtime plus its job channel and never creates or drops a runtime on the caller's thread.
- Errors: `openjiuwen_common::error::{Error, Result}`; adapters map kernel errors, never panic on user input; unsupported backends return `Error::Unsupported` with the backend name and the supported alternative.
- Serde: public wire types are `#[serde(rename_all = "camelCase")]` where the external protocol is camelCase (A2A, agent cards, OTEL attribute names, Langfuse bodies) and `snake_case` elsewhere; unknown fields are tolerated.
- Logging: `tracing` only (targets `openjiuwen_extensions::*`); no stdout/stderr writes in library code; credentials, payload contents and memories never logged above `debug`.
- Safety: no `unsafe`; no global mutable state beyond the documented Python-compatible process globals (the sandbox container cache keyed by base URL + isolation key, and the per-path conditional-write lock registry).
- Size: files ≤ ~1000 lines; one file per concern; shared helpers (status mapping, SSE framing, redaction, HTTP error mapping) live once at the module root.
- Intentionally large: `src/otel/workflow_handler/tests.rs`, `src/otel/agent_handler/tests.rs` and `src/otel/otlp/protobuf/tests.rs` are exhaustive callback/attribute/wire matrices that lose value if split; `tests/sandbox_providers.rs` (plus its `sandbox_providers/{teardown,conditional_write}.rs` modules) and `tests/redis.rs`, `tests/elasticsearch.rs`, `tests/context_evolver.rs` are one binary per provider/backend family; `src/sys_operation/remote/{jiuwenbox,yuanrong}.rs` carry their provider wire maps inline.
- Feature tests must pass offline: `cargo test -p openjiuwen-extensions` plus `--features a2a`, `--features otel`, `--features a2a,otel`, `--features sqlite`, `--features redis`, `--features pulsar`, and `--all-features`.

## Test Strategy

- Unit tests live beside the code that owns the behavior: `src/a2a/client/tests.rs`, `src/a2a/transform/tests.rs`, `src/a2a/harness_bridge/tests.rs`, `src/a2a/server/{tests,rest_tests}.rs` plus inline tests in `types.rs`, `jsonrpc.rs`, and `card.rs`.
- OTel unit tests: `src/otel/sink/tests.rs`, `src/otel/sink/tests/lazy_open.rs`, `src/otel/agent_handler/tests.rs`, `src/otel/workflow_handler/tests.rs`, `src/otel/otlp/tests.rs`, `src/otel/otlp/protobuf/tests.rs`, `src/otel/grafana/tests.rs`, the `src/otel/langfuse/*` suites, plus inline tests in `redaction.rs`, `span_names.rs`, `config.rs`, `env.rs`, `handle.rs`, `attrs.rs`, and `llm_attrs.rs`.
- Adapter unit tests live inline or in `tests.rs` siblings: `src/checkpointer/{mod,redis}.rs` (+ `redis/tests.rs`), `src/store/mod.rs` (+ `tests.rs`) and `src/store/redis/{mod,kv,document,vector}.rs` (+ `redis/tests/{kv,document,vector}.rs`), `src/store/elasticsearch/{mod,client,tests}.rs`, `src/redis/{client,codec}`, `src/message_queue/{mod,bridge,pulsar}.rs`, `src/sys_operation/{mod,remote/**}` (+ `remote/{teardown,conditional}.rs`, `remote/{jiuwenbox,yuanrong}/tests/teardown.rs`, `remote/backend/tests/conditional.rs`), `src/context_evolver/{mod,record,store,completion,memory_store,kernel_vector_index}.rs` + `service/` and `prompt/` modules, and `src/vendor_specific/mod.rs`.
- Observability utility unit tests are inline `#[cfg(test)] mod tests` beside each file: `src/observability/{project_semconv,redaction,content_addressing,tool_outcome,error_reporting}.rs` port the Python suites for their module (byte-for-byte literals, masking quirks, chain hashing, reference round-trips), and `src/observability/{file_exporter,transforming}.rs` cover the retention predicate, the append/cleanup cycle and export-time projection over `CaptureExporter` with `futures::executor::block_on`.
- `./tests/otel_file_exporter.rs` drives `ExporterType::File` end to end through `init_otel_tracer` into a `tempfile::TempDir`: one `traces-<today>.jsonl` per day, one single-span OTLP JSON request per line, hex ids, attribute round-trip, growth across exports, retention after the 64th export, `retention_days = 0` disabling cleanup.
- `./tests/otel_team_memory.rs` proves the `openjiuwen-agent-teams` team-memory → OTLP bridge from the receiving side: it rebuilds that bridge's component frames (`TraceFrame::workflow` + `TraceSpanKind::Component`, `component_type = "MemoryOperation"`, the `openjiuwen.meta_data` attribute bag) and asserts a three-frame batch reaches `wiremock` as one `POST /v1/traces` in both encodings, decoding the protobuf body with the shared reader; plus the no-op path over a shut-down or `ExporterType::None` handle and an infallible `emit` against a `500`.
- `./tests/support/mod.rs` holds the shared hand-written OTLP protobuf reader (`decode`, `messages`, `key_values`, `any_string`, …) used by `otel_otlp_protobuf.rs` and `otel_team_memory.rs`; it is `pub(crate)` because the workspace `unreachable_pub` lint rejects `pub` items in a private test module.
- `./tests/observability_deferred.rs` (always compiled) asserts one `ErrorKind::Unsupported` plus capability-and-alternative message per `observability::deferred` entry point, the exact instrumentation env-flag literal, the infallible `is_initialized() == false`, and the `ObservabilityDemand` wire round-trip.
- `src/a2a/e2e_tests.rs` keeps the in-crate public-path client/server suites; `./tests/a2a_client.rs` and `./tests/a2a_server.rs` mirror them as crate-boundary targets for external consumers.
- Module doctests in `src/lib.rs` and `src/otel/mod.rs` compile as external crates and carry the public seam/handler assertions; the OTel handler doctests are `#[cfg(feature = "otel")]`-guarded so the default build stays green.
- Crate-boundary suites under `./tests/` use only `openjiuwen_extensions::...` public paths: `a2a_client.rs`, `a2a_server.rs`, `a2a_rest.rs` (`#![cfg(feature = "a2a")]`), `otel.rs`, `otel_otlp.rs`, `otel_otlp_protobuf.rs`, `otel_team_memory.rs`, `otel_file_exporter.rs`, `otel_integrations.rs` (`#![cfg(feature = "otel")]`), `redis.rs` (`#![cfg(feature = "redis")]`), `otel_seam.rs` and `adapters.rs` (compiled in every build, with per-test feature gates), plus the always-compiled `elasticsearch.rs`, `sandbox_providers.rs`, `vendor_reranker.rs`, `context_evolver.rs` and `observability_deferred.rs`; `support/mod.rs` is the shared (test-only, non-suite) helper module.
- A2A: `wiremock` for the client (send, streaming SSE, cancel, error mapping) and `axum`'s `Router::oneshot` (via `tower::ServiceExt`) for the server routes; no real sockets unless a test binds `127.0.0.1:0`.
- OTel: the in-memory `CaptureExporter` records exported `SpanData`, so span names, attributes, statuses, dedup, and parenting are asserted without a collector; every capture test calls `force_flush()` first. The OTLP exporter is driven against `wiremock` in both encodings — the protobuf suite decodes the request bytes with a test-local decoder and one test encodes a single batch both ways to prove they agree — and the Grafana/Langfuse presets and Langfuse ingestion are driven against `wiremock` peers.
- Redis speaks RESP to an in-process fake server (key-value, document and vector suites); Elasticsearch, the sandbox gateways and DashScope use `wiremock`; the evolver's model path uses `wiremock` chat completions with a deterministic fallback suite that needs no peer.
- Sandbox teardown and conditional-write tests use loopback `wiremock` with a distinct isolation key per test; whole-cache drains go through one crate-internal guard (or a child process) so the process-global cache cannot interleave across the parallel test binaries.
- Deferred capabilities assert `ErrorKind::Unsupported` plus the message naming the missing piece and the supported alternative.
- Each ported behavior test names its Python counterpart (e.g. `tests/unit_tests/extensions/tracer_otel/test_redaction.py`) in a comment.
