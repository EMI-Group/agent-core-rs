# llm — models, configs, providers, clients

## Intent

Provider-neutral model invocation: the `Model` trait, the three transports (OpenAI-compatible chat completions, OpenAI Responses, Anthropic Messages), the serializable configs, and the provider registry/factory.
Ports `openjiuwen/core/foundation/llm/` (`model.py`, `schema/config.py`, `model_clients/*`).
Five side surfaces sit beside the transports: `reasoning/` (provider/model thinking profiles and wire encoders), `routing/` (IntelliRouter model groups, route compilation, ordered failover), `oauth/` (`OpenAI` account device authorization and token storage), `dashscope/` (`DashScope` image, speech and video generation over HTTP), and `external_provider/` (the external account-provider registry plus the `OpenAIAccount` credential manager and model catalog, porting `openjiuwen/extensions/external_provider/`).
They are independent of each other; `reasoning` is the only one the request builders call, `routing` is the only one that builds models, and `external_provider` composes `oauth` rather than duplicating a token call.

## API Surface

`config`:
- `ModelClientConfig { client_id, provider, api_key: Option<SecretString>, api_base: Option<String>, verify_ssl: bool /* true */, timeout: Option<Duration> /* 360s */, stream_first_chunk_timeout: Option<Duration> /* 300s */, stream_idle_timeout: Option<Duration> /* 60s */, max_retries: u32 /* 0 */, headers: BTreeMap<String,String>, api_mode: Option<ApiMode>, auth_mode: AuthMode /* ApiKey */, endpoint_profile: Option<String>, extra: Value }`
  Builders `new(provider)`, `with_api_key`, `with_api_base`, `with_timeout`, `with_max_retries`, `with_header`, `with_verify_ssl`, `with_api_mode`, `with_auth_mode`, `with_endpoint_profile`, `from_env()`; `resolve_for(provider)` applies env fallbacks and provider defaults; `sanitized_headers()` drops protected names (`host`, `content-length`, `transfer-encoding`, `connection`, `authorization`) and returns the rest.
  `ModelClientConfig::from_env()` reads only `MODEL_PROVIDER` (default `"openai"`), the key (`OPENJIUWEN_API_KEY` → `API_KEY` → `OPENAI_API_KEY`) and the base (`API_BASE` → `OPENAI_BASE_URL`), leaving every other field at its default; `ModelRequestConfig::from_env()` reads only `MODEL_NAME` (empty string when unset, so each transport reports the missing name itself).
  Neither reads `OPENJIUWEN_API_BASE`/`OPENJIUWEN_MODEL`/`OPENJIUWEN_PROVIDER` — those are `openjiuwen-harness` CLI-config variables that are mapped onto these configs by the CLI layer.
  serde aliases: `client_provider` → `provider`, `custom_headers` → `headers`; `ApiMode` (`chat_completions`/`responses`/`anthropic_messages`) and `AuthMode` (`api_key`/`none`/`custom_headers`/`openai_account_oauth`) use the Python wire spellings.
  Only `AuthMode::ApiKey` requires a credential; the other modes authenticate through caller headers, an account token, or not at all.
  Decoding follows Python's shapes (private `config::decode`): the three timeouts accept `float`/integer seconds (`360.0`), a numeric string, or the legacy `{"secs","nanos"}` object and serialize as a number of seconds (`null` stays `null`; zero/negative/non-finite values are serde errors, matching Python's `gt=0`); `headers` values may be strings, numbers, or booleans (coerced with `to_string()`), `null` values are dropped and arrays/objects are errors; unknown top-level keys are ignored.
- `ModelRequestConfig { model_name, temperature, top_p, max_tokens, stop: Vec<String>, context_window: Option<u32>, reasoning: Option<Value>, purpose: Option<String>, metadata: BTreeMap<String, Value>, tools: Option<Value>, tool_choice: Option<Value>, stream: bool, extra: Value }` with builders (`with_temperature`, `with_max_tokens`, `with_tools(Vec<Value>)`, `with_tool_choice`, `with_stop`, `with_stream`, `with_context_window`, `with_reasoning`, `with_purpose`, `with_purpose_assistant`, `with_purpose_compaction`, `with_metadata`, `with_metadata_entry`, `with_context_operation_id`, `with_extra`) and `from_env()`; serde alias `model` → `model_name`.
  `stop` decodes from Python's single optional string, `null`, or an array of strings and always serializes as an array; `context_window` (Python's internal context metadata) round-trips but is never written to a request body; `reasoning` is the typed provider-neutral intent (`Option<Value>`, `skip_serializing_if` none) that the three request builders read before the legacy `extra["reasoning"]` spelling.
  `purpose` (`skip_serializing_if` none) is an open-ended client-side reason for the call whose well-known values are `PURPOSE_ASSISTANT` (`assistant`) and `PURPOSE_COMPACTION` (`compaction`), and `metadata` (`skip_serializing_if` empty) holds caller-owned diagnostics such as `context_operation_id` or an evaluation run id; neither is read by a transport nor written to a provider body, and a default request serializes to exactly the previous key set.
  `effective_purpose()` resolves the purpose with precedence typed `purpose` (blank ⇒ unset) > legacy `extra["request_purpose"]` > legacy `extra["purpose"]` (trimmed JSON strings only, a non-object `extra` tolerated), `is_compaction()` compares it with `PURPOSE_COMPACTION`, and `extra_without_internal_keys()` returns `extra` minus the internal top-level keys for the builders to merge.

## Constraints

- Only `openjiuwen_common::http::HttpClient` performs I/O; no direct `reqwest` calls.
- `api_key` is a `SecretString`: never logged, never formatted; provider errors redact the body (`security::redact_str`) and truncate it to ~1000 chars.
- All bodies are built by pure functions (`build_chat_completion_body(_with_endpoint)`, `build_messages_body(_with_endpoint)`, `build_responses_body`) and parsed by pure functions, so tests can assert exact JSON without a server.
- `reasoning` is pure data plus pure functions: a `const`/`static` table, a hand-rolled `*`/`?` glob matcher, no I/O, no clock, no global mutable state, no new crate.
- `oauth` and `dashscope` also perform every request through `HttpClient`; no module calls `reqwest` directly, and no module adds a dependency.
- `routing` builds per-route models with `init_model` and never mutates a caller's configs: overrides are merged into owned copies (route `request_defaults` < group `request_config` < route `request_overrides`).
- Secrets (`api_key` of `ModelClientConfig` and `DashScopeConfig`, every OAuth token field) are `SecretString`s with redacting `Debug`; provider/vendor error bodies are redacted via `security::redact_str` and truncated before they reach an error message or a log.
- `provider` strings are case- and separator-insensitive: `normalize_provider_name` lowercases, strips `-`/`_`/spaces and maps vendor aliases.
- Streaming never panics on malformed events: undecodable SSE data is logged, counted by `SseDecoder::skipped_frames`, and skipped; a terminal `error` event becomes `Err(Error::Llm)`.

## Design Decisions

- **Config defaults** follow `ModelClientConfig` in Python (timeout 360 s, `verify_ssl` true, `max_retries` 0); `init_model_with` (the Python `init_model` analogue) uses the more permissive factory defaults (timeout 60 s, `verify_ssl` false, `max_retries` 3) — documented so callers are not surprised.
- **Environment fallbacks** (Python has none in this package, `docs/ARCHITECTURE.md` §4 requires them) come from `openjiuwen_common::config::env`: `MODEL_PROVIDER` (default `openai`), `OPENJIUWEN_API_KEY` → `API_KEY` → `OPENAI_API_KEY`, `API_BASE` → `OPENAI_BASE_URL` → provider default, `MODEL_NAME`. Explicit config always wins; the key precedence is the common helper's, not llm-specific.
- **Provider table is data, not code**: `openai` `https://api.openai.com/v1`, `qwen`/`dashscope` `https://dashscope.aliyuncs.com/compatible-mode/v1`, `deepseek` `https://api.deepseek.com/v1`, `moonshot` `https://api.moonshot.cn/v1`, `openrouter` `https://openrouter.ai/api/v1`, `siliconflow` `https://api.siliconflow.cn/v1`, `zhipu` `https://open.bigmodel.cn/api/paas/v4`, `minimax` `https://api.minimax.chat/v1`, `ollama` `http://localhost:11434/v1`, `lmstudio` `http://localhost:1234/v1`, `anthropic` `https://api.anthropic.com`.
  `pangu` is OpenAI-compatible but has **no** built-in base URL (air-gapped deployments), so it requires `api_base` and fails with `Error::Config` otherwise.
  `openai_account` is the one Responses-flavored entry (`https://chatgpt.com/backend-api/codex`, path `/responses`).
  No default model names are invented; `MODEL_NAME` or an explicit `model_name` is required.
- **The wire protocol is selected by data, not by the caller's class**: `ApiMode::Responses` on an `openai` provider flips the built-in factory to `OpenAiResponsesClient`, and `openai_account` always uses it; every other provider keeps its declared transport. `AuthMode` is recorded and only relaxes the credential requirement, so an account deployment can authenticate through caller headers instead of `api_key`.
- **`Model::stream` takes ownership** of messages/request so the returned stream is `'static`; `invoke` borrows. `BoxStream<'static, Result<StreamChunk>>` is built with `async_stream::try_stream!`.
- **Retries** are delegated to `HttpClient` (`RetryPolicy`, exponential backoff, retryable statuses); clients therefore set the retry budget from `max_retries` and do not implement their own loop. Streams retry only up to the connect boundary.
- **Timeouts**: per-request `timeout` on the HTTP request; streaming applies `stream_first_chunk_timeout` and `stream_idle_timeout` with `tokio::time::timeout`, yielding `Error::Timeout` (Python uses the same two budgets).
- **Error mapping**: 401/403 → `Error::Config` (auth), 408/504 → `Error::Timeout`, other non-2xx → `Error::Llm`, transport failures and JSON decode errors propagate from `HttpClient`/serde with `Error::transport`/`Error::Llm` context.
- **`finish_reason` semantics**: `None` until the provider reports one; when the response carries tool calls but no reason, `FinishReason::ToolCalls` is inferred. The Python `"null"` string sentinel is not reproduced.
- **Reasoning replay** is `openai::replays_reasoning_content(provider, model_name)`: canonical provider `deepseek` **or** a model name containing `deepseek` (Python's `model_requires_reasoning_content`). Those assistant turns always carry `reasoning_content` (`""` when absent, Python parity); other providers never see the field.
- **Sampling numbers** are `f32` in the config and rounded to six decimals when written, so `0.7` goes on the wire as `0.7` rather than the `f32` expansion.
- **Serialized config nuance**: `api_key`/`api_base` skip `None`, while the three `Option<Duration>` budgets serialize an explicit `null` so "disabled" survives a round trip instead of reverting to the default through `#[serde(default)]`.
- **Provider resolution**: a built-in `ModelProvider::create` fills a blank `client.provider` with its registered name before delegating (so `qwen` cannot silently become `openai`); `init_model` resolves the config for names in the static table and passes extension (non-table) names through with only the provider normalized, so extension providers own their env/default handling. `resolve` consults normalized aliases before the exact-name lookup, `register` replaces a same-name entry, and both return the replaced provider.
- **Error bodies are redacted in full**: `security::redact_str` replaces any non-empty body with `<REDACTED>`, so provider error prose never reaches logs; tests assert on status, error kind, and URL instead.
- **Async factory**: `init_model`/`init_model_with` stay `async` per `docs/ARCHITECTURE.md` §2.2 even though built-in providers construct synchronously, so provider creation can become async without a signature break.
- **Client request semantics**: `invoke`/`stream` use the `ModelRequestConfig` passed by the caller, never the constructor's; `model_name()` reports the constructor's request. A caller must therefore always pass a non-empty `model_name`.
- **Request purpose and metadata are client-side hints**: Python strips its internal per-call kwargs (`request_purpose`, `context_operation_id`) out of the provider kwargs before the body is built, so the Rust equivalents are typed fields (`purpose`, `metadata`) that no transport reads and no builder writes; the legacy `extra` spellings of the same keys stay accepted for ported call sites and are dropped by `extra_without_internal_keys()`, which all three builders merge in place of `extra`. Only top-level `extra` keys are stripped, so every unrelated key keeps its merge-last override semantics and a key nested inside the Responses-only `extra_body` is still forwarded; `RoutingEntry::effective_request` forwards the caller's purpose (falling back to the route's) with route plus caller metadata merged, so a failover attempt remains the same logical call.
- **Reasoning is opt-in and body-invisible otherwise**: every builder reads `request.reasoning` first and `request.extra["reasoning"]` second as a `ReasoningConfig`; with neither present the produced body is byte-identical to the pre-reasoning behaviour, and a caller's own `extra` keys are still merged last and win over the plan.
  A value typed on the field is always consumed (it is a field, not a body key), and a legacy raw payload keeps its old routing: forwarded under `reasoning` by the OpenAI-compatible and Responses builders, rejected as `Validation` by the Anthropic one.
- **Reasoning `extra_body` merges at the body top level**, unlike Python (whose OpenAI SDK nests `extra_body` and folds it in before the request); the body this crate builds is the wire body, so the nesting would be wrong.
- **An endpoint profile names the wire dialect**: `ModelClientConfig::endpoint_profile` is trimmed, lowercased and `_`→`-` normalized; a non-generic value (`vllm`, `dashscope`, …) wins over the provider name and the host hint, while a generic one (`""`, `openai`, `openai-compatible`) defers to the host and then to the provider as written, matching Python's `_provider_key_from_values`. Both clients pass their config's profile and resolved base URL into the request builders, so a self-hosted `vllm` gateway receives the `enable_thinking`/`chat_template_kwargs`/`thinking_budget` encoding instead of `thinking.type`/`reasoning_effort`.
- **Reasoning never guesses beyond the profile**: an intent the family's capability cannot express drops only the unsupported `effort`, keeps the explicit mode/budget encoding, and records one warning; a family with no selectable control yields an empty plan plus one warning.
- **Routing is additive to the Python schema**: `priority` and `tag` on a route are Rust extensions for rule/priority routing; with no priority anywhere the route list order is preserved, so a ported configuration routes exactly as in Python.
- **Routing failover is bounded and selective**: the attempt budget is `min(num_retries + 1, candidates)`, only transport/timeout/`Llm`/`External` failures fall over, and a stream fails over only before its first chunk.
- **Routing budgets and deadlines are enforced**: every route's `rpm`/`tpm` reserves in a rolling 60 s bucket keyed by `provider/model`, reconciles with the reported usage, and waits on the injected `Clock`; a request that cannot fit inside the attempt deadline is a typed `Error::Timeout` naming TPM/RPM. Each attempt runs under the route's own `timeout_seconds` (group value as fallback), and a timeout is an ordinary retryable failure.
- **DashScope reuses the shared error taxonomy** rather than a vendor error enum: non-2xx is `Error::Llm`, `401`/`403` become `Error::Config`, `408`/`504` and an exhausted task budget become `Error::Timeout`, and vendor `code`/`message` are surfaced truncated.
- **OAuth state lives in the auth file, not in memory**: `OpenAiOAuthClient` reads and writes a `TokenStore` per call, so two processes observe the rotated refresh token; writes take the `<auth_file>.lock` advisory lock, are atomic (`temp` + `rename`, `0600` on unix), and are a read-merge-write of the `providers.OpenAIAccount` entry. Reads stay lock-free, and a token with no resolvable expiry counts as expired, so it is refreshed instead of being handed out forever.
- **Responses conversation state is per client**: `new` mounts a fresh in-memory LRU store, `with_session_store` swaps it, request-level hints beat client-level ones, and an explicit `extra["previous_response_id"]` always wins over the store; no process global exists.

## OpenAI-compatible wire contract

- Request: `{model, messages, stream}` plus `temperature`/`top_p`/`max_tokens`/`stop` when set, `tools`/`tool_choice` only when tools are present (`tool_choice` defaults to `"auto"`), and `extra` merged last (caller wins, with the internal purpose/metadata keys stripped first). `stream: true` adds `stream_options: {"include_usage": true}`.
- Messages: `{"role", "content"}`; assistant turns add `tool_calls: [{id, type:"function", function:{name, arguments}}]` (arguments is the JSON string) — and replay `reasoning_content` for DeepSeek-like providers (see the predicate above); tool turns add `tool_call_id`. Parts pass through verbatim (provider-shaped), so no normalization happens here.
- Tolerances accepted on the wire: a response message object where a stream `delta` is expected, flat tool-call fragments in streams, a provider SSE frame carrying `{"error": ...}` (becomes `Error::Llm` with a redacted message), and an empty `choices` array (treated as framing so `include_usage` frames parse).
- Response: `choices[0].message` → `BaseMessage` (`content` string or parts; `tool_calls` flattened with `index`); `usage.prompt_tokens`/`completion_tokens`/`total_tokens`, `prompt_tokens_details.cached_tokens` → `cache_tokens`, `completion_tokens_details.reasoning_tokens` → `reasoning_tokens`.
- Stream frames: `data: {...}` lines terminated by `data: [DONE]`; `choices[].delta.content` → `content`, `.reasoning_content` → `reasoning`, `.tool_calls[]` (with `index`, `id`, `function.name`, `function.arguments`) → `ToolCallDelta`, `.finish_reason` → `finish_reason`, `role` on the first frame; choice-less frames carrying `usage` → `StreamChunk::Usage`; every stream terminates with `StreamChunk::Done`.

## Anthropic wire contract

- Request: `POST {base}/v1/messages` with `x-api-key` (never `authorization`) and `anthropic-version: 2023-06-01`; `normalize_api_base` strips a pasted `/v1/messages` or `/v1` before the client appends the profile path.
- Body `{model, messages, max_tokens, stream}` plus `temperature`/`top_p`/`stop_sequences` when set, `tools`/`tool_choice` when applicable, and `extra` merged last (caller wins, with the internal purpose/metadata keys stripped first).
  `max_tokens` is required: `request.max_tokens` else 32768, capped at 8192 for `claude-3-5*`/`claude-3.5*` and 4096 for `claude-3-opus|sonnet|haiku`; an explicit larger value is capped too.
  The top-level `system` field is a block array with one `{"type":"text","text":…}` per non-empty `system`/developer turn, in order (non-text parts skipped, field omitted when no system turn exists); a mid-conversation system turn is hoisted as its own block, or kept inline for the model families that accept it — the full placement and cache-anchor rules live in `./anthropic/CONTEXT.md`.
  `build_messages_body_with_endpoint(messages, request, stream, provider, endpoint_profile, api_base)` resolves an `extra["reasoning"]` intent through `ReasoningProtocol::AnthropicMessages` and merges the plan into the body (`thinking`/`output_config`, or `enable_thinking`/`thinking_budget` for an `endpoint_profile` of `vllm`); `build_messages_body_with_provider` delegates with no profile and `build_messages_body` with provider `"anthropic"`.
  `MessageContent::Text` goes out as a plain JSON string for user/assistant turns; part lists become block arrays.
  Assistant `tool_calls` → `{"type":"tool_use","id","name","input":<parsed JSON>}` (unparseable arguments → `{"_raw_arguments": "..."}`, a missing id is `Error::Validation`); consecutive `tool` messages merge into one `user` message of `{"type":"tool_result","tool_use_id","content":<text>}` blocks (a missing `tool_call_id` is `Error::Validation`).
  Images: `data:<mime>;base64,<payload>` → base64 `source`; `http(s)` urls → url `source`; any other URL is `Error::Validation`. Audio/file/unknown parts pass through verbatim.
  Tools: OpenAI-shaped `{"type":"function","function":{...}}` → `{name, description, input_schema}` (other shapes pass through); `tool_choice` mapping `auto`→omitted, `required`/`any`→`{"type":"any"}`, `none`→`{"type":"none"}`, `{"function":{"name":N}}`→`{"type":"tool","name":N}`; `stop` → `stop_sequences`.
- Response: `content` text blocks concatenated into `message.content`, `tool_use` → `ToolCall` with `arguments = json.dumps(input)` and index = position among tool_use blocks, `thinking` text appended to `message.reasoning_content` with replayable `thinking`/`redacted_thinking` blocks preserved in metadata; `stop_reason` mapping `tool_use` → `ToolCalls`, `end_turn`/`stop_sequence` → `Stop`, `max_tokens` → `Length`, else `Other`; usage `input_tokens` = `input_tokens` + `cache_read_input_tokens` + `cache_creation_input_tokens`, `cache_tokens` = cache read.
- Stream: `message_start` (role + first usage), `content_block_start` (text or `tool_use` with id/name), `content_block_delta` (`text_delta`, `thinking_delta`, `input_json_delta` buffered per index), `content_block_stop` (emit the accumulated `ToolCallDelta` for `tool_use`, `"{}"` when empty), `message_delta` (`stop_reason` + merged usage), `message_stop` (one `Done`), `ping`/unknown events ignored, `error` events → `Error::Llm` with only the redacted error type/message.
- Three `cache_control: {"type":"ephemeral"}` anchors are always written (last tool, last system block, last cacheable block of the last stable message), with `extra.disable_cache_control` and `extra.cache_control_ttl` as the only knobs; a streamed thinking turn surfaces `reasoning` but not replayable signatures (see `./anthropic/CONTEXT.md`).

## Test Strategy

- Unit tests live beside their modules: `config`, `model`, `provider`, `registry`, `factory`, `sse`, `transport`, `openai/{request,response,stream}`, `anthropic/{request,response,stream}`.
- `./config/decode.rs` tests the Python-decoding helpers through mirror structs wired exactly like the real fields (float/integer/numeric-string/`{secs,nanos}`/`null` durations, non-positive and unparsable values, single-string/`null`/array `stop` with unknown-type errors, and string/number/bool/`null`/array header values); `./config/tests.rs` re-asserts them end to end on `ModelClientConfig`/`ModelRequestConfig`, including the exact serialized JSON (`"timeout": 360.0`), the typed `reasoning`/`context_window` round trip, and that unknown Python keys stay out of `extra`.
- Each request-builder suite proves the typed `reasoning` field produces the same body as the equivalent `extra.reasoning` config, that the typed field wins when both are set, that a typed legacy payload is still forwarded (OpenAI/Responses) or rejected (Anthropic), and that `context_window` never appears in a body.
- Wiremock end-to-end tests live in `./openai/tests.rs` and `./anthropic/tests.rs` (declared from each client's `mod.rs`): request URL/headers/body, streamed SSE assembly, retry after a `500`, `401` → `Error::Config`, malformed body → `Error::Llm`.
- Streaming timeout budgets are tested against a loopback stalling server, never a real provider.
- No test touches the network or a real credential; `MODEL_PROVIDER`/`API_KEY`/`API_BASE` mutations are serialized by a module mutex and restored.
- `cargo test -p openjiuwen-foundation llm` covers the whole module in both feature sets; the module has no feature-gated code.
- `responses` tests live in `./responses/{request,response,stream,state}.rs` (pure projection/parsing/event/LRU tests) and `./responses/tests.rs` (wiremock end-to-end for request shape, headers, streaming assembly, error mapping, factory dispatch, and the `previous_response_id`/`max_tool_calls` conversation flow).
- `reasoning` is covered by table-driven tests (`./reasoning/tests.rs`, `./reasoning/plan_tests.rs`, `./reasoning/vllm.rs`): glob matching, provider/alias/host-hint/`endpoint_profile` precedence, fallback on the full id and its last `/` segment, the vLLM switch/budget matrix on both protocols, and the exact JSON of every encoder in enabled/disabled/effort/budget shapes, plus capability rejection and apply merge/no-overwrite rules.
- `openai/request.rs` additionally asserts that a body with no `reasoning` intent carries no reasoning keys at all and stays byte-identical, and that the endpoint-aware builder writes `enable_thinking`/`chat_template_kwargs`/`thinking_budget` (never `reasoning_effort`) for a `vllm` profile while a profile-less or non-vLLM build matches the plain builder byte for byte.
- `oauth` tests drive every endpoint through `wiremock` (device code, `403`→`404`→`200` polling, exchange, refresh with and without rotation), exercise `FileTokenStore` round trips, envelope merging, unix `0600`, atomic-write leftovers and `default_path` env precedence with `tempfile`, cover the unresolvable-expiry refresh, and prove `login`/`status`/`logout` plus the two-handle `flock` semantics (`try_lock`/bounded wait/`Timeout`) in `credential_tests.rs` and `lock_tests.rs`.
- `dashscope` tests assert exact image/speech/video request JSON and headers, parse both URL and inline-base64 responses, and cover async task polling `PENDING`→`RUNNING`→`SUCCEEDED`, `FAILED`, and a bounded task timeout (millisecond-scale poll budgets, so the suite stays fast).
- `routing` tests cover schema round trips, merge precedence/deep merge/stripped keys, every compile error, priority ordering, wiremock end-to-end failover (`500`→`200`, `401` not retried, `num_retries = 0`, tag pinning, stream failover only before the first chunk), and the `ManualClock`-driven RPM/TPM reservation/reconciliation and attempt-deadline cases.
- OAuth and DashScope env mutations are serialized by a module mutex and restored, so the suite stays deterministic under `--test-threads` defaults.
- `./config/purpose_tests.rs` covers purpose/metadata in 12 tests: the JSON round trip, the Python-shaped decode, the unchanged default request shape, the builders, `effective_purpose` precedence (including blank, non-string values and a non-object `extra`), `is_compaction`, and internal-key stripping.
- Each transport suite (`openai/request.rs`, `responses/request.rs`, `anthropic/request.rs`) additionally asserts on the built body that the internal keys are absent, that a legacy `extra` purpose is honoured and stripped, that an unrelated `extra` key is still merged last, and that a non-object `extra` leaves the body unchanged.
- `external_provider` tests live in `./external_provider/registry_tests.rs` (builtin availability, alias folding, fresh instance per creation, unknown/empty-name and duplicate-registration errors, local-vs-global isolation) and `./external_provider/openai_account/tests.rs` (pure model-list parsing, wiremock-backed credential/catalog calls with `Authorization: Bearer`, cache round trip and corrupt/absent files, forced and expiring refresh, `default_cache_path` env precedence) — offline, temp directories, `InMemoryTokenStore`, fixed clock, no credentials.

## Known Gaps

- There is no `ModelInputs`/`ChatParams`/`ModelIo`-style wrapper or inbound/outbound conversion trait: callers pass `&[BaseMessage]` to `invoke`/`ModelExt::complete` and an owned `Vec<BaseMessage>` to `stream`.
- There is no `response_format`/`ResponseFormat` type, field, or helper and no history/`enable_history` flag anywhere in the crate: structured output and every vendor knob go through `ModelRequestConfig::extra`, which `build_chat_completion_body` merges last at the top level.
- There is no `BoxModel`/`type Model = …` alias; `Arc<dyn Model>` is the convention (`init_model`, `init_model_with`, `ModelProvider::create`) and `impl Model for Arc<dyn Model>` makes it callable directly.
- `Model` exposes only `provider()`, `model_name()`, `invoke()` and `stream()`: there is no `name()`, `config()`, or cancellation method on the trait.
- Reasoning: both request builders receive the client's `endpoint_profile` and resolved base URL, so the host hint and the endpoint profile are reachable from every client; `resolve_reasoning_plan`/`provider_key_for` remain the profile-less entry points, and an OpenAI-compatible raw (`non-intent`) `reasoning` payload is forwarded verbatim while the Anthropic transport rejects it with `Error::Validation`.
- Reasoning: the self-hosted `vllm` endpoint profile is selected only by `endpoint_profile` (no host is hardcoded), and the `Responses` protocol has no vLLM encoder — its plan stays the `reasoning.effort`/`reasoning: null` encoding.
- Routing: there is no cross-request circuit breaker, cooldown state, or tag-based cost/latency scoring, `Custom` strategies are rejected by the compiler and treated as ordered failover by `RoutingModel`, and the Python `extra_body` flattening/health-probe options are not ported. RPM/TPM and `timeout_seconds` are enforced per route inside one `RoutingModel`, and the limiter state is per instance rather than process-global.
- OAuth: `llm::oauth` itself has no `/models` call; `AuthStatus` and the cached model catalog live in `external_provider`, and an `AuthMode::OpenAiAccountOAuth` client still authenticates with a caller-supplied bearer key rather than reading the auth store inside the client. The cross-process lock is unix-only: other platforms return `Error::Unsupported` and keep atomic-but-unserialized writes.
- `external_provider`: auth-store writes inherit `llm::oauth`'s unix-only cross-process lock while the model-cache file is written atomically with no cross-process lock, the stored `auth_mode` marker is `openai_account_oauth` rather than Python's `openai_account`, the factories take the typed `ExternalProviderConfig` instead of Python `**kwargs`, and Python's `start_device_login`/`poll_device_login` stay in `llm::oauth`; no path in the subtree emits `Error::Unsupported`.
- Responses: `invoke` always streams, so a provider that answers one JSON object instead of an event stream cannot be decoded; conversation state is in-memory only (lost on restart), `background` mode and hosted tools are typed `Unsupported`, and replay of encrypted reasoning items is not implemented; `File`/`Audio` input parts are dropped.
- Responses: `prompt::ToolCall` has no `response_item_id`, so the provider's output-item id (`fc_…`) is discarded by the parsers and a replayed `function_call` input item always carries the call id in its `id` slot; Python keeps the item id on `ToolCall.response_item_id` and emits `id = response_item_id or call_id`.
- `SseDecoder` has no maximum frame size: bytes are buffered until a `\n`, so a provider that streams a very long line grows the pending buffer without bound.
- `Instant::now() + timeout` is used unchecked for the DashScope video task budget (`dashscope/client.rs:184`) and the first-chunk deadline of the OpenAI-compatible and Responses streams (`openai/mod.rs:290`, `responses/mod.rs:436`), so a caller-supplied or deserialized duration near `Duration::MAX` panics instead of returning a typed error; `routing::limit` already does this with `checked_add`.
- The Anthropic body writes `temperature`/`top_p` with `Value::from(f32)` and no finiteness filter (`anthropic/request.rs:197`), while the OpenAI-compatible decoder rounds to six decimals and drops non-finite values (`sampling_value`), so `0.7` reaches Anthropic as `0.699999988079071` and a non-finite value becomes `null`.
- DashScope: no streaming media, no result-URL byte download, no `X-DashScope-WorkSpace` scoping, no voice/language allow-lists, no local-file/`oss://` inputs, and no per-call `**kwargs` escape hatch.
- OpenAI-compatible: Python drops one of `temperature`/`top_p` for `openai.com` bases; this module sends both when the caller sets both.
- Anthropic: thinking blocks are preserved on both paths — non-streaming `thinking` text becomes `reasoning_content` and replayable `thinking`/`redacted_thinking` blocks are stored in metadata, while streamed `thinking_delta` becomes `reasoning` without replayable signatures — and only the three automatic cache anchors are exposed (no per-message caller breakpoints, no `clear`/`auto` caching modes).
- A provider that keeps sending framing-only stream events can hold a stream open indefinitely when `stream_idle_timeout` is `None`.
- Unknown Python config keys are ignored rather than forwarded into `extra` (Python's `model_config = {"extra": "allow"}` keeps them on the model); only the documented aliases and the typed fields survive a cross-language round trip.
- A Python `reasoning` payload that is not an intent object (a raw legacy dict) is forwarded verbatim by the OpenAI-compatible and Responses builders but rejected with `Error::Validation` by the Anthropic builder, which has no raw `reasoning` body key to forward it to.
- A `float` `max_tokens`/`context_window` (`512.0`) is not coerced to an integer the way pydantic's lax mode does; only the integer JSON form decodes.
- Two documented Anthropic wire facts have no test: that the client sends only `x-api-key` and never `authorization` (the wiremock suite matches `x-api-key`/`anthropic-version` positively and never asserts header absence), and that an `event:` name wins over a payload `type` when both are present (`anthropic/stream.rs::event_name`; only the missing-`event:` fallback is tested).
