# openjiuwen-dev-tools

## Intent

Developer tooling for authoring, generating, evaluating, and tuning openJiuwen artifacts: prompts, skills, agents, and workflows.
Maps the Python package `openjiuwen.dev_tools` (`prompt_builder/`, `skill_creator/`, `agent_builder/`, `skill_evaluator/`, `tune/`).
The crate is a layer-5 consumer of the kernel: it builds on `openjiuwen-foundation` prompts and `Model`, on `openjiuwen-agent` cards/configs, and on the kernel retrieval loaders (`openjiuwen_core::retrieval`) for non-text documents.
Audience: tool authors writing Rust programs (and the CLI/dev tooling above this crate) that generate, validate, evaluate, and optimize agent assets.
Python's dev tools are LLM-orchestration scripts with little typed surface; the Rust port keeps the observable artifacts (prompt text, skill bundles, agent DSL/configs, workflow designs, score reports, tuning traces, run logs) and replaces free-form LLM contracts with typed models, deterministic cores, and an optional `Model` seam.

## API Surface

Crate root `openjiuwen_dev_tools` with one module per Python subpackage plus a shared scoring module:

- `judge` — rubric-driven LLM judgement shared by `skill_evaluator` and `tune`: `Rubric`/`RubricDimension` (weights, scale, validation, weighted `normalize`), `Verdict`/`VerdictSource` (tolerant structured parsing of fenced JSON, tag sections, bare JSON; percent strings; provenance), `prompt::{system_prompt, render_rubric, rubric_messages}`, `ModelJudge` + `Judge`/`JudgeRequest`, and `judge_with_fallback` returning a deterministic verdict when the model call or parsing fails.
- `prompt_builder` — `MetaTemplateBuilder` (task description → standardized prompt), `FeedbackPromptBuilder` (feedback → rewritten prompt), `BadCasePromptBuilder` (evaluation cases → repaired prompt); bundled `zh-CN`/`en-US` prompt banks, deterministic formatting/parsing helpers.
- `skill_creator` — `SkillDefinition` (name/description/instructions/resources/metadata), `SkillCreator` (create from `SkillSpec` or from a `Model`, template rendering, bundle write/read, `create_from_url`), `SkillBundle` (harness-compatible `SKILL.md` + resources layout), and `skill_creator::omni` — the `skill_omni_creation` pipeline: `Fetcher` seam (`HttpFetcher` over `openjiuwen_common::http`, `ScriptedFetcher`), rule-based `HtmlDocument`/`resolve_url`, and `OmniCreation` stages scrape → download → generate → save → `OmniOutcome`.
  `skill_creator::omni::archive` is the archive layer: `ArchiveFormat`/`ArchiveEntry`/`ArchiveEntryKind`/{File, Directory, Symlink, HardLink}, `detect` plus `detect_named` (suffix fallback for `.tar.bz2`/`.tbz2`/`.tar.xz`/`.txz`/`.tar.zst`/`.zstd`), `ArchiveUnpacker::{unpack, unpack_auto, unpack_with_options, unpack_auto_with_options}` with `UnpackOptions::password` for ZipCrypto entries, `ArchiveWriter::write_stored`, in-crate inflate and CRC-32, path safety, and per-entry/per-archive uncompressed-size caps.
  The archive readers cover TAR (PAX `x`/`g` records and GNU `L`/`K` long names applied, link entries exposed with their target, two-zero-block end of archive), ZIP (ZIP64 end-of-central-directory/locator/extra fields and skipped digital-signature records, ZipCrypto decryption, unix symlink modes, stored and DEFLATE entries) and gzip (including gzip-wrapped tar/ZIP); bzip2/xz/zstd and WinZip AES/PKWARE strong encryption are typed `Error::unsupported` naming the codec or scheme.
  The rest of `omni` is the in-crate `sha256` helper (`digest`/`hex_digest`), the Python-parity image extension/MIME allow-lists (`SUPPORTED_EXTS`/`SUPPORTED_MIMES`, `image_extension`, `sniff_image`, `filter_images*`, `slugify`, `dedupe_links`), header-only image dimensions (`filter::image_dimensions` for PNG/JPEG/GIF/WebP/PNM) feeding the decorative-image gate, image persistence at `references/img_NN.<ext>` with `saved_path`/`sha256` provenance, `strip_hallucinated_images` against those persisted paths, and exactly one `## Reference Files` block per generated document.
  `omni::pipeline::documents` extracts text from fetched PDF/DOCX/XLSX/PPTX/ODT (and text/Markdown/CSV/JSON) resources through `openjiuwen_core::retrieval::loaders::AutoLoader`, dispatching on URL suffix then content type; `GenerationProvenance` distinguishes a model-drafted skill from the deterministic template with a `warn!`, and `OmniOutcome::provenance` carries it.
- `agent_builder` — programmatic `LlmAgentSpec`/`WorkflowSpec` and serialized platform DSL (`LlmAgentDsl`, `WorkflowDsl`), the `to_agent_card`/`to_llm_agent_config`/`build_llm_agent` bridge into `openjiuwen-agent`, `HistoryManager`, and the session-based `AgentBuilder`.
  The staged pipeline is composed of the intention detector (`IntentionDetector::{detect_initial, detect_refine}`, `IntentionVerdict`, `BuildIntent`), the bounded `Clarifier` dialogue (`ClarifyConfig`, `ClarificationRound`, `ClarificationDialogue`, `ClarificationTermination`, `clarify_rounds`), `WorkflowDesigner`/`WorkflowDesign` with `design`, `design_offline`, `design_three_pass` (basic → branch → reflection) and `design_with_provenance`, `DlGenerator` (`generate`, `from_spec`, `generate_with_model`, `generate_candidate`, `refine`), `DlReflector`/`Reflection` for graph repair plus `DlReflector::validate_dl` for Python's per-node-type DL rules (including duplicate input/output names, multi-placeholder values and undeclared references), `cycle_checker::{find_cycle, has_cycle}`, `mermaid::{render_mermaid, render_design}` in Python's grammar (`graph TD`, `  {id}[Node{id}: {label}]`, `-- label -->` only on a multi-successor source, plus `when_condition_label` for `When condition met[...]` labels), and `AgentBuilder::build_with_pipeline`/`build_with_pipeline_stream` (intention → clarify → design → generate → reflect/refine within `DEFAULT_MAX_RETRIES` → validate).
  Intent ids in `DlCondition` are `Uuid::new_v4()` unless the DL supplies one; DL→platform conversion (`dl_transformer`) fills plugin ids and versions from the matched `PluginResource` or the DL node config.
  `dl_transformer` is the DL→platform-DSL conversion layer (`DlDocument`/`DlNode`/`DlNodeType` → `PlatformWorkflow`): numeric node-type ids, `meta.position` steps of +20, `_of_` input/output variable splitting, plugin/questioner/branch/code defaults, recursive null-dropping, and `PlatformWorkflow::to_workflow_dsl`.
  `outcome` owns the provenance contract: `GenerationSource` {Model, Deterministic, Fallback}, `StageProvenance`, `GenerationProvenance` (per-`ProgressStage` records, `has_deviation`/`has_fallback`/`warn_if_degraded`), `RepairReport`, and `BuildResult.{provenance, repair}`.
  `utils` (`extract_json_from_text`, `format_dialog_history`, `merge_dict_lists`, `validate_session_id`) and `progress` (`ProgressStage`, the two stage-weight tables, `progress_for`) carry the Python helper modules.
- `skill_evaluator` — `EvalCase`, deterministic `Assertion`/`CaseRunner` seams, `DesignReport`/`FunctionalReport`/`SafetyReport`/`FinalScore` models with the Python aggregation (`0.40·design + 0.60·pass_rate`, configurable safety gate defaulting to `0.80`), and `SkillEvaluator`.
  `judge_scoring` adds `design_rubric`/`safety_rubric`, `SkillJudge` with `with_gate_threshold`/`safety_with_threshold` (the configured gate gates the score, reaches `scan_safety`, and is the value reported in `SafetyReport::gate_threshold`), `SkillEvaluator::with_judge`/`evaluate_with_judge`/`evaluate_with_judge_at` with deterministic fallback and `JudgeRecord` provenance.
  `react` is the ReAct functional runner: `ReactCaseRunner` (bounded model-turn → tool-call → tool-result loop, `DEFAULT_MAX_REACT_ROUNDS`, `with_stubs`/`with_tool_declarations`/`with_max_rounds`/`with_system_prompt`, `ReactOutcome.{answer, trace, rounds, truncated}`) plugging into the `CaseRunner`/assertion path.
  `eval` is the runnable harness: `load_cases_json`/`load_cases_file` (JSON array, `{"cases": […]}` object, single object, JSONL), `EvalAgent`/`ModelAgent`/`CaseRunnerAgent`, `EvalHarness::{run, run_query}`, `EvalRun::{to_json, to_json_string, to_jsonl, write_json, write_jsonl}`, and `QueryRequest`/`QueryOutcome` mirroring `run_eval_query.py`'s output-path resolution.
  `artifacts` writes the four Python JSON files — `llm_judge_score.json`, `skill_safety_score.json`, `skill_tester_report.json`, and `final_score.json` (skipped unless the pipeline completed) — through `ArtifactPaths`, the per-file `EvaluationReport::write_*_report` methods, and `write_artifacts`; `artifacts::markdown` renders and writes the four human-readable reports (`llm_judge_report.md`, `skill_safety_report.md`, `final_report.md`, `pipeline_report.md`) through `MarkdownArtifactPaths`, with `final_report.md`/`pipeline_report.md` mutually exclusive exactly like `final_score.json`.
  Units: every `*_pct`, `contribution`, `pass_rate`, and gate threshold (`gate_threshold`, `safety_gate_threshold`, `DESIGN_GATE_THRESHOLD`) is a 0.0–1.0 fraction, while `design_score`, `design_score_max`, and `ScoreDimension::{score, max}` stay 0–100 points.
  Status tokens are `COMPLETED`, `BLOCKED_AT_E1`, and `BLOCKED_AT_E3`, gate roles are `GATE_E1`/`GATE_E2`/`GATE_E3` (a completed run reports only `e3_safety`), and `SafetyReport::auto_fail` is an `Option<AutoFailCode>` over AF1–AF5.
  `timestamp::iso8601_utc` renders caller-supplied epoch milliseconds as `YYYY-MM-DDTHH:MM:SSZ` (in-crate civil-date arithmetic), and `FunctionalReport::timestamp_iso()` exposes it beside the `i64` field.
- `tune` — `Case`/`EvaluatedCase`/`CaseLoader` (Python field names), `Case::from_text`, `CaseLoader::split_tagged`/`CaseSplit`, the evaluator seam (`PromptRunner`/`ModelPromptRunner`/`ScriptedPromptRunner`, `CaseScorer`/`LabelScorer`, `CaseEvaluator`/`RunnerEvaluator`/`ModelEvaluator`/`DeterministicEvaluator`, `EvaluatedRun`/`evaluate_run`/`score_runs`), `OptimizerConfig`/`PromptSearchConfig`, `OptimizationResult` (`train_score`/`val_score`/`selected_on`), the four searches (`InstructionOptimizer` beam search, `ExampleOptimizer` greedy example selection bounded by `config.iterations` and ranking each round on at most 16 evenly spaced cases, `JointOptimizer` alternating ascent, `PromptSearchOptimizer` bounded elitist loop with memory warm start, run log, adopt decisions and a convergence break), `ParameterSearcher`/`ParameterSearchOutcome` plus `generate_candidates`/`candidate_space` (spaces above `MAX_MATERIALISED_CANDIDATES` are sampled from mixed-radix indices instead of being expanded), `Trainer` (`train`, `evaluate_split`, `train_split`), and `optimize_prompt`.
  `tune::dataset` adds the sampler/scheduler layer: `CaseSampler` with `SequentialSampler`/`RandomSampler::new(seed)`/`StratifiedSampler::new(seed)`, `BatchScheduler` (batch size, epochs, seeded shuffle, drop-last) yielding `Epoch`/`Batch` with epoch, batch, global-step and input-index metadata, and `SplitDataset` over `CaseSplit::{Train, Val, Unspecified}`.
  `tune::chat_agent` binds an optimizer to an agent: `ChatConfig`/`create_chat_config` (validated ids, model name, system/user prompts, temperature/top_p, freeze flags), the `ChatRunner` seam with `ModelChatRunner` and offline `ScriptedChatRunner`, and `ChatAgent` implementing `PromptRunner` with `evaluator`/`optimize`/`train`.
  `tune::binding` is the parameter/tool binding layer: `TextualParameter`, `ParameterBinding` (placeholder-set equality, `apply` → `ParameterUpdate`, `apply_result`), `BoundAgent`, and `ToolBinding`/`ToolBindingReport` built on `Case::tools()` + `ToolStubs`.
  `tune::optimizer::adopt` ports the adopt family over the injected `DriftJudge`/`PromptMemory`/`ConvergenceDetector` seams: `AdoptConfig`, deterministic `AdoptPolicy::decide` with `AdoptReason`, `AdoptMemory`, `AdoptService`, `GradientPolicy`/`DeterministicGradientPolicy`, and `select_bad_cases`/`select_good_cases`.
  The `tool` layer covers tool-aware evaluation: `ToolStub`/`ToolStubs`, the `ToolHandler` alias (`dyn Fn(&Value) -> Result<Value>`), `ToolCallRecord`/`ToolTrace`, `RunOutcome`, and `ToolUsageScorer`, with `DEFAULT_MAX_TOOL_ROUNDS` bounding the model tool loop.
  The traced surface is `PromptRunner::run_traced`, `CaseScorer::score_with_trace`, `CaseEvaluator::evaluate_traced`/`score_cases_traced`/`tool_usage`, and `Trainer::evaluate_traced` → `EvaluationSummary` (`mean_score`, `results`, `tool_usage`, `split`); optimizer prompts render the case set's declared tools as a `<tools_description>` block.
  `RunTelemetry` ({latency, prompt/completion tokens, cost}, all optional) travels with `RunOutcome`/`CaseResult`/`Execution`, so `LatencyReward`/`TokenUsageReward`/`CostReward` score on measured values and stay constant only when the seam reports none.
  `tune::prompt_search` is Python's RLAF layer: `PromptTaskCase`/`PromptTaskSpec`/`PromptCandidate`/`CaseResult`/`Execution`/`RewardBreakdown`/`Evaluation`/`IterationRecord`/`PromptRecord`, `min_max_normalize` plus the `RewardComponent` family (`CorrectnessReward`, `CompletenessReward`, `LatencyReward`, `TokenUsageReward`, `CostReward`, `StructuredValidationReward`, `CustomReward`) composed by `CompositeReward` with `OVERFIT_MARGIN`/`OVERFIT_PENALTY`, the correctness gate, drift penalty and error zeroing, `ConvergenceDetector`/`ConvergenceState`, `PromptMemory`/`JsonlPromptMemory`/`NullPromptMemory`, `OptimizationHistory`/`HistoryEntry`/`HistoryCompressor`, the `DriftJudge` seam (`NullDriftJudge`/`LexicalDriftJudge`/`ModelDriftJudge`), and `run_log` (`RunLogRecord` including the pre-round elite, `RunLog` with `JsonlRunLog`/`NullRunLog`/`InMemoryRunLog`, tolerant `read_run_log`/`read_run_log_limited`).

Cross-module rules: `Case`/`EvaluatedCase` are owned by `tune` and consumed by `prompt_builder` (`BadCasePromptBuilder`) — never duplicated; rubric scoring lives in `judge` and is consumed, never re-implemented, by `skill_evaluator` and `tune`; the adopt layer consumes the `prompt_search` seams; `skill_evaluator::react` consumes `tune::{ToolStubs, ToolTrace, ToolCallRecord}`.
Tool descriptors use `openjiuwen_foundation::tool::ToolInfo` (the wire `{"type":"function","function":{…}}` shape); Python's flat `ToolInfo` is not reproduced.

## Constraints

- Only this crate may be edited here; workspace manifest, sibling crates, and `docs/` are out of scope.
- No new dependencies: HTTP is `openjiuwen_common::http` (workspace `reqwest` stack); HTML, tar, zip (including ZIP64 and ZipCrypto), gzip, DEFLATE, CRC-32, SHA-256, image sniffing/dimensions, ISO-8601 civil dates and URL resolution are implemented in-crate. bzip2/xz/zstd decoders are impossible offline (no crate in `Cargo.lock` or the local registry cache) and stay typed `Unsupported`.
- `Cargo.toml` declares `openjiuwen-core` and `thiserror = "2"`; `openjiuwen_core::retrieval` is used by `skill_creator::omni::pipeline::documents` for non-text extraction, while `thiserror` still has no source or test reference.
- Async-first: builders, optimizers, trainers, and the harness are `async fn`; streams return `BoxStream<'static, Result<…>>`; no `block_on`/`asyncio.run` bridging — synchronous Python entry points become `async` (documented deviation, e.g. `Trainer::train`).
- Streaming exists in `prompt_builder` (`MetaTemplateBuilder`/`FeedbackPromptBuilder`/`BadCasePromptBuilder::stream_build`) and in `agent_builder` (`Clarifier::stream_clarify`/`ClarifyEvent`, `WorkflowDesigner::stream_design`/`DesignEvent`, `AgentBuilder::build_with_pipeline_stream`/`PipelineEvent`, which is the single implementation behind the buffered pipeline); `skill_creator`, `skill_evaluator`, and `tune` expose no stream entry point.
- Provenance is never silent: every staged builder records `GenerationSource` per `ProgressStage`, logs one `warn!` per degraded stage (`warn_if_degraded`), and surfaces the fallback on the result (`BuildResult::provenance`, `OmniOutcome::provenance`) with serde defaults so older JSON still parses.
- The crate has exactly seven `Error::unsupported` construction sites, all in `skill_creator::omni::archive` (bzip2/xz/zstd refusals in `archive/mod.rs`, non-DEFLATE `CM` in `gzip.rs`, WinZip AES / PKWARE strong encryption / encrypted central directory / unknown method in `zip/mod.rs`, and a ZIP64 value that exceeds the platform `usize` in `zip/zip64.rs`); every other deferred area is absent code or a documented single-pass substitute, so `tests/deferred_surface.rs` pins only the remaining archive refusals.
- Errors: `openjiuwen_common::error::{Error, Result}` only; invalid user input is `Error::validation`, missing capability is `Error::unsupported`, model failures propagate as `Error::llm`.
- Model failures never silently degrade: an optional model path falls back to a documented deterministic path (never an empty result), and the fallback is visible (returned value, `VerdictSource`, `GenerationSource`, or `used_fallback`).
- Serialization: public data types are `serde` (`rename_all = "snake_case", default`), unknown-field tolerant; DSL, report, `Case`, `RunLogRecord`, `OptimizationResult`, and provenance JSON keep the Python field names, and new fields carry serde defaults.
- No `unsafe`; `tracing` logging via `openjiuwen_common::logging`; no `println!`/`eprintln!`; no panics on user input (archive and image parsing are bounds-checked on hostile bytes).
- Files around ≤1000 lines; one responsibility per file; shared helpers within a module, not duplicated across modules (one `tune::prng::Rng64` backs every seeded shuffle).
- Deliberately long files: `skill_creator/omni/archive/zip/tests.rs` (~1600 lines) is the per-codec archive matrix and loses coherence if split; `skill_creator/omni/pipeline.rs` (~1100) and `pipeline/tests.rs` (~1200) keep the scrape/download/generate/save orchestration and its scenario suite together.
- Tests are offline and deterministic: `openjiuwen_test_support::ScriptedModel` for model-driven paths, `TempWorkspace` for filesystem bundles, `ScriptedFetcher`/loopback `TcpListener` for HTTP, scripted chat runners for `tune::chat_agent`, fixed ids and caller-supplied timestamps — no wall-clock reads, no environment reads.
- Empty prompts, blank skill names, unknown template names, malformed frontmatter, empty rubrics, out-of-range tuning parameters or gate thresholds, blank refinement feedback, and archive/image malformed input are validation errors or typed refusals, never silent fallbacks (Python's "warn and degrade" behavior is a documented deviation).

## Design Decisions

- Python builders own a `Model`; here every builder, optimizer, judge, and stage takes an optional `Arc<dyn Model>` (or `ScriptedModel` in tests), so configuration stays with the caller and nothing reads the environment.
- Deterministic cores are public: template rendering, message assembly, JSON-fence/tag parsing, skill frontmatter rendering/parsing, agent/workflow DSL transformation, Mermaid rendering (including `When` labels), cycle detection, HTML/archive/image-header parsing, samplers, label comparison, run-log formatting, ISO-8601 conversion, and evaluation scoring are ordinary functions testable without a model; the model only supplies text.
- Every model-driven stage is validated structurally before it is accepted (DSL must `validate`, a design must pass `WorkflowDesign::validate`, a skill definition must `validate`, a judgement must parse); an unusable answer falls back to the deterministic path instead of erroring.
- The repair loop is genuinely closed: `DlGenerator::generate_candidate` keeps a parsed-but-invalid model document with its validation notes, so the bounded reflect → refine → reflect loop can rescue it within `DEFAULT_MAX_RETRIES`; a document that never validates degrades to the deterministic baseline with `Fallback` provenance, and a rescued document is reported as model-derived.
- Provenance is derived from what was actually used, not from whether a model was attached: `Model` only when the accepted document came from model text, `Fallback` when a model answer was rejected, `Deterministic` when no model ran.
- `judge` is the single scoring LCA: `Rubric::normalize` is the only weighted-score implementation, `Verdict::parse` is the only verdict parser, and `ModelJudge::judge_with_fallback` is the only model→deterministic fallback contract; `skill_evaluator`'s safety gate has one owner (`SkillJudge::gate_threshold`, fed from `EvaluatorConfig::safety_gate_threshold`).
- `tune`'s search is deterministic by construction: fixed mutation banks, ordered candidate generation, seeded PRNG, seeded stratified/random sampling, and a total tie-break (score desc → earlier candidate index → lexicographically smaller prompt or `case_id`); `DeterministicEvaluator` gives an offline run a real gradient, `ModelPromptRunner` plus `LabelScorer` replace it when a model is available, and `CompositeReward` scoring stays pure arithmetic over `Execution`/`Evaluation`/`RunTelemetry`.
- Held-out data stays held out: the trainer optimizes on the train split only, `OptimizationResult` records `train_score`/`val_score`/`selected_on`, and tests prove no evaluator call ever mixes splits and no val-only token reaches a candidate prompt.
- Tool awareness stays additive in `tune`: a `ToolTrace` travels only through the traced methods and `EvaluationSummary`, `EvaluatedCase` gains no field, and an untraced evaluation scores exactly as before.
- `skill_evaluator` keeps one unit convention: fractions for every ratio and threshold, points only where Python reports points, and `round4`/`fraction_from_points` as the only scale conversions.
- Optimizer configuration is explicit (`OptimizerConfig`) and validated against the Python `TuneConstant` bounds; `optimize_prompt` is the no-config convenience over `InstructionOptimizer`.
- `agent_builder` keeps Python's two artifacts (platform DSL JSON and kernel config) and composes them; the legacy one-round-trip `build_agent`/`build_agent_at` stays available, while `build_with_pipeline` (and its stream) runs intention → clarify → three-pass design → generate → reflect/refine, with a deterministic fallback at every stage.
- `skill_evaluator`'s functional score stays assertion-based; `ReactCaseRunner` adds tool-executing evaluation through the same `CaseRunner` seam, the LLM judge covers design and safety only, and a `scan_safety` finding always overrides a passing model verdict (hard gate).
- `skill_creator::omni` keeps fetch, parsing, and generation separate: `Fetcher` is injected, HTML parsing is rule-based and tolerant, archive/image handling is byte-level pure code, document extraction delegates to the kernel loaders, and the skill document is generated deterministically unless a model is supplied (with the provenance saying which).
- The run log reports elite movement honestly: `RunLogRecord.best_score` is the round's best, `prior_best_score` is the elite entering the round (optional for round 1/legacy lines), and `is_improvement()` is true only when the round advanced the elite; `selected` keeps its elite-movement meaning.

## Test Strategy

- Unit tests inside each module (`#[cfg(test)]`) cover deterministic transforms, validation errors, fallbacks, model-driven paths with `ScriptedModel`, and serialization round-trips; larger suites live in sibling `tests.rs` files or `tests/` directories split by concern (`judge`, `tune::{evaluator, prompt_search, optimizer::{adopt, search, trainer}}`, `omni/{html,archive,filter,pipeline,documents}`, `skill_evaluator::{scoring, eval, judge_scoring, artifacts, artifacts::markdown}`, `agent_builder::{designer, builder, clarifier::{rounds}, dl_reflector, dl_generator, dl_transformer::convert}`, `intention`).
- The archive layer is tested per codec: `omni/archive/{zip,gzip,inflate}` and `zip/{zip64,zipcrypto}` keep `tests.rs` siblings while `tar` keeps its own `tests.rs`, covering the format matrix, the stored-ZIP round trip, ZIP64 resolution/rejection, ZipCrypto round trips and wrong-password/AES refusals, symlink/hardlink entries, PAX/GNU long names, DEFLATE golden streams, gzip member/CRC-ISIZE verification, truncated-input validation errors, and the size caps.
- Image handling is covered by `omni/filter/{dimensions,tests}.rs`: header parsing for PNG/JPEG/GIF/WebP/PNM, malformed input returning `None`, and the `< 80x80` decorative gate both ways.
- Non-text extraction is covered by `omni/pipeline/documents/tests.rs` (fixture documents through the retrieval loaders, content-type dispatch, loader-failure text fallback, blank-extraction validation) and the integration suite.
- Tool-aware tuning is covered by `tune/tool.rs` (stub lookup, records, trace coverage/missing/usage), `tune/evaluator/tests.rs` (the model tool loop, `ToolUsageScorer`, `evaluate_traced`, the `EvaluationSummary` round trip) and `tune/evaluator/telemetry_tests.rs` (telemetry-carrying rewards).
- The staged builder is covered by `agent_builder/{clarifier/rounds/tests.rs, designer/passes/tests.rs, designer/stream/tests.rs, builder/pipeline_tests.rs, builder/stream_tests.rs, intention/tests.rs, dl_generator/tests.rs, dl_reflector/tests/**, dl_transformer/convert/tests/**}`: loop termination order, three-pass fallbacks, intent detection, candidate rescue and rejection by the repair loop, streaming-vs-buffered parity, uuid4 intent ids, duplicate/placeholder rules, plugin-node resolution, and the `When` label grammar.
- `tune`'s new layers are covered by `tune/{dataset/*, chat_agent/*, binding/tests.rs, optimizer/adopt/tests.rs, prompt_search/run_log_tests.rs, optimizer/search/run_log_tests.rs, optimizer/trainer/tests.rs}` plus the in-node cross-module suite `src/tune/integration_tests/` (dataset → scheduler → tagged split → trainer, held-out isolation, telemetry rewards, adopt over `JsonlPromptMemory`, run-log round trip, binding through an optimizer, chat agent offline).
- `skill_evaluator` suites cover the configurable gate (0.70/0.80/0.90 directions plus invalid values), the ReAct loop and its budget/truncation, the four Markdown reports including the blocked variant, and the ISO-8601 conversion against known epochs.
- `crates/openjiuwen-dev-tools/tests/` holds 11 public-API binaries (95 tests): `skill_lifecycle` (author→bundle→evaluate, ReAct runner), `prompt_assets` (`tune`→`prompt_builder`), `agent_assets` (spec→DSL→`LlmAgent`, session builder), `agent_stages` (intention, clarify rounds, three-pass design, refine, Mermaid labels, DL rules, plugin nodes), `agent_pipeline` (pipeline provenance, repair convergence, stream parity), `omni_bundle` (fetch→bundle, archive matrix, provenance, image dimensions), `omni_documents` (PDF/DOCX/XLSX/PPTX/ODT extraction), `tuning_pipeline` (loader→samplers→splits→optimizers→trainer→run log), `tuning_adapters` (binding, adopt, chat agent, telemetry rewards), `judge_and_pipeline` (judge provenance, gate thresholds, Markdown reports, eval harness, `build_with_pipeline`), and `deferred_surface` (the remaining archive refusals).
- Model-driven paths assert both the result and the request: queued `ScriptedModel` turns plus recorded call inspection.
- No network, no environment reads, no wall-clock dependence: ids and timestamps are parameters or fixed constants.

## Deferred

- Archive coverage stops at the offline-implementable set: bzip2/xz/zstd input and WinZip AES, PKWARE strong encryption, encrypted central directories, and compression methods other than stored/DEFLATE are typed `Error::Unsupported` naming the codec or scheme; the ZIP writer is stored-only, so nothing here writes compressed ZIP entries.
- Python `skill_omni_creation` Playwright/JS rendering, stealth/cookie handling, Pillow pixel decoding/size gates, and the multimodal image-relevance judge — replaced by static-DOM extraction, header-only dimension parsing, byte/format filters, and an optional text model; a browser/vision stack is out of scope, as are OCR of scanned PDFs and video frames.
- Agent-builder conversion gaps: platform plugin/knowledge/prompt-template retrieval (`transform_with_resources` takes caller-supplied `PluginResource`s), variable-type validation helpers (`available_variable_types`/`check_type`), the `ProgressReporter` singleton and callbacks, and Python's branch-operator parsing beyond the second whitespace token.
- `tune` keeps cases in memory and drives optimizers through caller-supplied evaluators: Python's `prompt_search` policy/environment/service layer, the `LLMCall`/`OptimizeHistory` binding classes (this port offers `TextualParameter`/`ParameterBinding` instead), dataset sources backed by external stores, and the Python agent runtime inside `chat_agent` (a `ChatRunner` seam here).
- `skill_evaluator`'s Python `create_subagent` environment-driven model construction is replaced by the caller-supplied `EvalAgent`/`ReactCaseRunner` configuration; `FunctionalReport::timestamp` stays epoch milliseconds with `timestamp_iso()` as the rendered form.
- `openjiuwen-dev-tools/tests/` integration coverage targets public-API seams; module internals are tested in-tree.
