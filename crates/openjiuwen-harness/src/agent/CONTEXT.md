# agent
## Intent
The `DeepAgent` facade: configuration, builder/factory assembly, single-round and task-loop invocation, streaming, follow-up/steering/abort, pause/resume, mode switching, and session-persisted state.
Ports `openjiuwen/harness/deep_agent.py` and `factory.py`; `DeepAgent` composes the kernel `ReActAgent` and never re-implements the model/tool loop.
## API Surface
- `DeepAgent::new(AgentCard)`, `configure(DeepAgentConfig) -> Result<()>` (validates first: an invalid config is rejected with the Python `__post_init__` message and the installed config, prompt, kernel settings, permission policy and tool set stay unchanged), `ensure_initialized()`, `invoke(inputs, session)` / `stream(inputs, session)` (impl `openjiuwen_agent::Agent`), `follow_up(msg, task_id)`, `steer(msg)`, `abort()`, `start()/stop()`, `send_input(SendInputRequest)`, `phase()`, `switch_mode(mode)`, `load_state()`/`save_state()`/`clear_state()`, `tool_cards() -> Vec<ToolCard>`, `add_rail(Arc<dyn HarnessRail>)` / `register_rail(Arc<dyn AgentRail>)`, `rails()`, `subagent_spawner() -> Option<Arc<dyn SubAgentSpawner>>`, `drain_rail_events() -> Vec<InteractionEvent>`.
- `DeepAgentBuilder`: `new(card)`, `config(DeepAgentConfig)`, `model(Arc<dyn Model>)`, `sys_operation(SysOperation)`, `workspace(Workspace)`, `tool(Arc<dyn Tool>)`/`tools(...)`, `rail(Arc<dyn HarnessRail>)`, `permission_host(Arc<dyn PermissionHost>)`, `user_asker(Arc<dyn crate::tools::UserAsker>)`, `memory(Arc<dyn MemoryRecall>, Arc<dyn MemoryWriteBack>)`, `subagent_factory(Arc<dyn SubAgentFactory>)`, `build() -> Result<Arc<DeepAgent>>`.
- Model: when no model is supplied, `ensure_initialized` builds one lazily from `DeepAgentConfig` (`model_client_config` + `model_config`, falling back to the flat `model_name`/`model_provider`/`api_key`/`api_base`/`custom_headers` fields) through `openjiuwen_foundation::llm::init_model`; impossible configuration → `Error::config`.
- `create_deep_agent(model: Arc<dyn Model>, card: Option<AgentCard>, config: Option<DeepAgentConfig>, tools: Vec<Arc<dyn Tool>>, rails: Vec<Arc<dyn HarnessRail>>, workspace: Option<Workspace>, skills: Vec<String>, subagents: Vec<SubAgentConfig>, enable_task_loop: bool, max_iterations: Option<u32>, language: Option<String>, prompt_mode: Option<PromptMode>, restrict_to_work_dir: bool, permissions: Option<PermissionsSection>, permission_host: Option<Arc<dyn PermissionHost>>) -> Result<Arc<DeepAgent>>` (`factory.rs:249`).
- No public `state()`, `messages()`, `history()`, `session()` or `inner()` accessor: `state: Arc<RoundState>`, `last_session: Arc<Mutex<Option<Arc<dyn Session>>>>` and `inner: Arc<ReActAgent>` are private fields; `RoundState::{last_result, token_usage, last_output}` are public but unreachable through `DeepAgent`.
- Conversation history is not held in memory by the facade: the kernel persists its `ContextEngine` contexts into session state key `context` (`openjiuwen-agent/src/react/agent_loop/mod.rs:368` `save_contexts`, `openjiuwen-context/src/engine.rs:56`) but never calls `ContextEngine::load_contexts`, so a new `DeepAgent` starts its `"main"` context empty even when the session state carries one — unless the host seeds it explicitly through `DeepAgent::seed_history` (see `./seed.rs`).
- Kernel seed recipe a resume entry needs: `ReActAgent::context_engine()` (public, `openjiuwen-agent/src/react/mod.rs:324`) plus `ContextEngine::create_context_with("main", ContextOptions { session, history, .. })` (`openjiuwen-context/src/engine/pool.rs:58-70`), whose `history` is applied only when the `(session.id(), "main")` pool key is new (`pool.rs:20-23,80,142-144`); an already-created context is seeded with `ModelContext::set_messages` (`openjiuwen-context/src/context/history.rs:85-89`), because the loop's later `create_context` returns the existing entry and ignores options (`openjiuwen-agent/src/react/agent_loop/mod.rs:480-483`, `pool.rs:48-52,81-83`).
- `ReActAgent::configure`/`DeepAgent::configure` replace the context engine and drop every pooled context (`openjiuwen-agent/src/react/mod.rs:200-232`, `mod.rs:238`), so a seed must follow the last configure and precede `invoke`/`stream`.
- `DeepAgentState` has exactly five fields (`iteration`, `task_plan`, `stop_condition_state`, `pending_follow_ups`, `plan_mode`) — no `messages`/`Vec<BaseMessage>`/history field — so `load_state`/`save_state` can seed plan/iteration/follow-ups but never a prior transcript.
- The only public seam that injects messages into a model call without a crate change is a caller `HarnessRail`: `before_model_call(&mut HarnessRailContext)` exposes `ctx.base.messages` mutably, and `PromptRail` (priority 5, last) only rewrites `messages[0]`/appends sections, so caller-inserted turns survive for that model call but are not persisted.
- The kernel fires `BeforeModelCall` once per ReAct iteration, after `ContextEngine::prepare` has already put the system message first (`openjiuwen-agent/src/react/agent_loop/mod.rs:527-551`), so a seeding rail must gate itself to the first call of a turn; a default-priority (50) caller rail runs before `PromptRail`, which re-inserts the rendered system message at `messages[0]` (`prompt_rail.rs:27,150-165`).
- External tools enter through `Vec<Arc<dyn Tool>>` and are appended to the inner `ReActAgent` (`builder.rs:235-238` then `wire` → `inner.add_tools` at `builder.rs:420`; later additions via `apply_extra_tools` → `inner.add_tool`, `mod.rs:476`); the harness `ToolRegistry` only builds the builtin set and is not a mutable external-tool registry.
- `DeepAgentParts { config, rails, tools }` + `resolve_deep_agent_parts(...)` (pure assembly), `apply_deep_agent_parts(agent, parts)`.
- Rail-event drain (`rail_events.rs`): `drain_rail_events(&mut HarnessRailContext) -> Vec<InteractionEvent>`, `RailEventBus` (`new(capacity)`, `push(event)`, `drain()`, `len()`, `is_empty()`, `capacity()`, `dropped()`), `RailEventDrain` (a `HarnessRail` named `rail_events` with `priority` `RAIL_EVENT_DRAIN_PRIORITY` = `i32::MIN`), `RailEventDrain::new(Arc<RailEventBus>)`, `RAIL_EVENTS_EXTRA_PREFIX` (`harness.events.`), `RAIL_EVENT_DRAIN_NAME`, `DEFAULT_RAIL_EVENT_CAPACITY` (256), plus `RoundExecutorHandle::with_rail_events(Arc<RailEventBus>)`.
- `state_store`: `load_state(&dyn Session)`, `save_state(&dyn Session, &DeepAgentState)`, `clear_state(&dyn Session)` under session state key `deepagent`.
- `seed_history(&self, session: &Arc<dyn Session>, history: Vec<BaseMessage>) -> Result<()>` (inherent `DeepAgent` method, `seed.rs`) fills the kernel `(session.id(), "main")` context: an existing context is replaced with `ModelContext::set_messages`, an absent one is created through `ContextEngine::create_context_with` with `ContextOptions::history`; it must follow the last `configure`/`build` and precede `invoke`/`stream`, and it is idempotent (empty `history` is legal).
- `seed_state(session: &dyn Session, state: Value) -> Result<()>` (free function re-exported from `agent`) replaces the persisted `deepagent` lane with a host-built JSON object verbatim, rejecting a non-object payload with `Error::validation`; replace (not deep-merge) semantics match `save_state`, and the keys are the host's, not validated against `DeepAgentState`.
- Input normalization: string, `{"query": ...}`, or an interactive/resume payload; reserved keys consumed, others become prompt variables; a non-string/non-object or a missing `query` → `Error::validation` (Python `DEEPAGENT_INPUT_PARAM_ERROR`).
## Constraints
- Composition: `DeepAgent` owns an `Arc<ReActAgent>` (kernel) and mounts harness rails through `HarnessRailAdapter`; tools are mounted on the inner agent from one `ToolRegistry`.
- `DeepAgentConfig` is serde data; live handles only through the builder. Missing/unbuildable model → `Error::config`.
- One invocation at a time per `DeepAgent`: a second concurrent invocation returns `Error::config`/`Error::validation` ("invocation already running"), never interleaves session state.
- Task loop runs only when `config.enable_task_loop`; otherwise exactly one ReAct turn. `max_iterations_hard_limit` still lowers the inner budget.
- State is saved after every task-loop round and after a single round; resume payloads never append a duplicate user message.
- Streaming: `BoxStream<'static, Result<AgentChunk>>`; inner `llm_output`/`llm_reasoning` frames pass through, `__interaction__` frames surface to the caller, and `RoundExecutorHandle::stream_turn` always ends with one `AgentChunk::answer` carrying the round's full `AgentOutput` (`round.rs:316`); `DeepAgent::stream` only skips its own duplicate terminal frame when `output.is_interrupt()` (`mod.rs:568`), so an interrupt stream is the interaction frames followed by exactly one terminal `answer` chunk with `result_type: "interrupt"`; a pre-flight error or a lost single-run race is delivered as exactly one `Err` item.
- Cancellation: `abort()` is synchronous, idempotent (`CancellationToken::cancel` + `TaskLoopController::request_abort`); the in-flight round observes it and yields `RoundOutcome::abort()`.
- No `unsafe`, no process globals; `Arc<DeepAgent>` is shareable; locks (`parking_lot`) are never held across `.await`.
- Errors: `openjiuwen_common::error::{Error, Result}`; Python `build_error(code, msg)` text is preserved in the message.
- Secrets never logged (`api_key` is `SecretString`); `tracing` only, CLI owns stdout.
## Design decisions
- **Prompt assembly**: `DeepAgent` builds a `HarnessPromptBuilder` from the config (identity from `system_prompt` else the card description, safety, tools from the mounted cards, workspace, task loop when enabled, mode instructions, todo when a plan exists, subagent section when subagents exist) and the inner `ReActAgent` receives that static text as its single `system` `prompt_template` message.
  Per-invocation sections published by rails (`skills`, `memory`, `subagent`) are rendered by `PromptRail` (a `HarnessRail`, priority 5, i.e. last) in `before_model_call`: it replaces the leading system message with `builder.build()` plus published sections that have no static counterpart, deduplicated by section name.
  This keeps the prompt pure data assembly (`crate::prompts`) and gives rails the documented `PROMPT_SECTIONS_EXTRA_KEY` channel.
- **Steering**: `PromptRail` also drains `LoopQueues::steering` in `before_model_call` and appends one `user` message per steering input (`User steering: <content>`) to the model window, so steering lands on the next model call without restarting the round; `before_steering_drain` fires from `round.rs` before the inner invoke.
  Steering text is not persisted to the session message history (documented deviation: the kernel has no mid-run user-message API).
- **Task loop ownership**: `DeepAgent` stores `controller: Arc<parking_lot::Mutex<Option<TaskLoopController>>>`; `invoke` takes the controller out, awaits `TaskLoopController::run_until_idle(&RoundExecutorHandle)`, and puts it back, so no lock is held across `.await` and the `stream` task (which owns no `Arc<DeepAgent>`) can restore it.
  `RoundExecutorHandle` is a separate `Send + Sync` value holding `Arc`s only (inner `ReActAgent`, `HarnessRailRegistry`, `LoopQueues`, cancellation token, session, `RoundState`), so it never borrows `DeepAgent`.
  The stored controller is reused only when it is neither aborted nor cancelled nor `Terminated`; otherwise a fresh controller is built through `make_controller`, so a latched abort never poisons the next round.
- **Sessions**: `invoke`/`stream` resolve the run session through `openjiuwen_agent::run::resolve_session`; a `None` session becomes an owned `AgentSession` named from `conversation_id` (default `default_session`) with `agent_id` set to the card id, and `parent_session_id` is forwarded when present.
  The state is loaded from and persisted on the resolved session, `last_session` records the resolved session, and an owned session is finished (`AgentRun::finish`) after the invocation while a borrowed one is left untouched.
- **Driver**: `pub(crate) struct Driver` snapshots the Arc fields of the facade; `DeepAgent::driver()` builds one, `invoke` runs it inline and `stream` moves one into the spawned task (the whole reason the fields are `Arc`-wrapped). Wiring lives in `builder::{wire, ensure_agent_wired}`, invoked by `build()` and the public `ensure_initialized()`.
- **Round granularity**: one task-loop round = one `ReActAgent::invoke` call. `run_round` fires `on_user_message` + `before_steering_drain`, runs the inner invoke, maps `AgentOutput` (`error` → `RoundOutcome::failed`, `interrupt` → successful round with `next_work = None` so the loop ends and the caller sees the interrupt), and fire `after_task_iteration`/`before_task_iteration` around task-loop rounds through `HarnessRailRegistry::fire_task_iteration`.
- **Follow-ups**: `follow_up` pushes onto the shared `LoopQueues`; a running loop consumes one follow-up per round (`is_follow_up = true`); an idle agent queues it for the next `invoke`, and `DeepAgentState::pending_follow_ups` persists the queue between sessions.
- **State**: `state_store` uses `Session::get_state("deepagent")` / `Session::update_state({"deepagent": ...})` and `DeepAgentState::to_session_dict`/`from_session_dict`; a missing key or non-object payload degrades to default with a debug log, a `Session` read error surfaces `Error::session`, and object payloads are decoded by the (lenient) `from_session_dict` — there is no strict "corrupt object" failure mode.
  `save_state` emulates Python's replace-style `update_dict` in two writes — `{"deepagent": null}` deletes the lane, then the full dict is written into the absent path — because the session store deep-merges objects and treats a `null` patch value as a delete; explicit nulls therefore survive repeated saves (`task_plan`/`stop_condition_state` and all four `plan_mode` keys stay present).
  After each task-loop round the controller's `StateSink` pushes the state into an unbounded mpsc channel drained by a spawned writer task that calls `state_store::save_state` (the sink is sync, the session API async); the writer is awaited and joined after `run_until_idle`.
  `save_state`/`load_state`/`clear_state` are the explicit entry points and operate on the session captured by the last `invoke`/`stream` (`Error::validation("no session bound to this DeepAgent")` when there is none).
  A persistence failure at the end of an invocation is logged (`tracing::warn!`), never propagated — an answer is never lost to a persistence hiccup.
- **Resume seeding is explicit**: `seed.rs` adds `DeepAgent::seed_history`, which fills the `(session.id(), "main")` pool entry through `ModelContext::set_messages` (existing context) or `create_context_with` + `history` (absent context) and must run after the last `configure` (which replaces the engine and drops pooled contexts) and before `invoke`/`stream`; the companion `seed_state` writes a host-built `deepagent` payload in the same two-write replace sequence as `save_state` instead of deep-merging it, and `agent` still never imports `persistent_agent`.
- **Subagents**: `SubAgentRegistry::with_builtin_presets(language)` + `SubAgentRuntime` with a `DeepAgentSubAgentFactory` that builds a nested `DeepAgent` from `SubAgentConfig` (depth 1: nested agents never mount subagent tools again), re-rooted at `<workspace>/sub-agents/<sub_session_id>` and inheriting the parent's model and language.
  `subagent_factory::SubagentMode` resolves the mounted tool set with the precedence `Runtime` (`enable_subagent_runtime`) > `AsyncSession` (`enable_async_subagent`) > `SyncTask`; `TaskTool` is always mounted, the async mode adds `subagent_spawn`/`subagent_wait`/`subagent_list`/`subagent_close`, and the runtime mode adds the seven `subagent_tools_with_transcript` tools.
  Subagents are wired only when `subagents` is non-empty or `add_general_purpose_agent` is set.
- **Tool retries**: `resilience::apply` maps `enable_tool_resilience_rail` onto the kernel `openjiuwen_agent::policy::ToolResiliencePolicy` — 3 attempts with a 100 ms initial backoff for idempotent cards, a single attempt for every non-idempotent card, an empty policy when the flag is off — and runs from `build`, `configure` and `apply_extra_tools` through `inner.set_tool_resilience(..)`; there is no rail object because the kernel never fires `RailEvent::OnToolException`.
- **Access boundary**: `config.project_root` reaches the mounted tools through `ToolRegistry::with_project_root` (`ToolEnv::with_access_root`) and the permission engine through `PermissionEngineConfig::with_project_root`, so an absolute path argument outside the root is refused by the tool (`Access denied: '<path>' is outside the project root.`) and denied by the engine (matched-rule suffix `|project_root`); relative paths stay workspace-sandboxed and `None` keeps the cwd/workspace behaviour.
- **Invocation journal**: `config.invocation_log_dir` opens one `invocation_log::InvocationJournal` per resolved turn in `Driver::run_resolved` and appends one bounded JSON object per turn (ids, role, query, answer, status, tool-call and iteration counts, timestamps, `truncated`); the bounds are 1024-char text, 4096-char entries, 128 KiB per file with oldest-entry trimming and 256-char identifiers, and every IO failure is a `tracing` warning, never a failed turn.
- **Permissions**: `config.permissions` builds one `Arc<PermissionEngine>` shared by `ToolRegistry::with_permissions` and `PermissionInterruptRail`, which is registered on the inner agent (priority 90) when permissions are enabled; the `PermissionHost` defaults to `NoopPermissionHost`.
- **Phases**: `InteractionPhase` mirrors the controller (`Idle`/`Running`/`Terminated`); `start`/`stop` drive the controller token, `send_input` routes `FollowUp`/`Steer` (mode `None` → follow-up when idle, steer while running) through `LoopQueues`.
- **Rail events**: rails have no event sink, so a rail that publishes an `InteractionEvent` appends `InteractionEvent::to_output_value()` frames under `harness.goal_events` (the goal key) or any `harness.events.*` key; `RailEventDrain` runs last at every firing point (priority `i32::MIN`), in the harness registry and on the inner agent through the adapter, so it also covers kernel hooks such as `after_invoke`.
  It moves the entries into the agent's `RailEventBus`, which forwards each event to the live invocation stream as an `__interaction__` frame and retains at most `DEFAULT_RAIL_EVENT_CAPACITY` events (oldest dropped first) for `DeepAgent::drain_rail_events()`; events survive across rounds and invocations until collected.
  `round.rs` also drains the contexts it builds itself after each `fire_*` call, so the seam works without the drain rail registered; the drain removes entries from `extra` first, so nothing is drained twice, and unrelated `extra` entries are never touched.
  Draining happens in `extra` key order (then array order), so events of one round keep a deterministic order.
- **Read-only agent access**: `rails()` returns the harness registry; `register_rail` forwards kernel rails to the inner `ReActAgent`; `add_rail` registers a harness rail in both the harness registry and (via `to_agent_rails`) the inner agent.
## Interrupt / resume contract

- Interrupt mapping: `RoundExecutorHandle::run_round` maps `ResultType::Answer | ResultType::Interrupt → RoundOutcome::answer(None)` (`round.rs:362-363`), `ResultType::Error → RoundOutcome::failed("deepagent_error", output.output)` (`:365`), an `Err` from `execute` → `RoundOutcome::failed("round_execution_error", …)` or `RoundOutcome::abort()` when the token is cancelled (`:370-375`), a failing before-iteration hook → `failed("rail_error", …)` (`:356-358`), and a pre-cancelled round → `RoundOutcome::abort()` (`:339-341`).
- The task loop is interrupt-agnostic: an interrupt is a successful round with `next_work = None`, so the loop stops for lack of work (`stop_reason = None`, not `aborted`); no interrupt frame or id ever reaches `task_loop`.
- `invoke` still returns the interrupt: `report_output` prefers `handle.last_output()` (`mod.rs:872-879`), so the inner `AgentOutput` (`result_type: "interrupt"`, `output: ""`, `state` = `__interaction__` frames, `interrupt_ids`) is returned verbatim.
- Resume payloads bypass the task loop: `normalize_inputs` copies an object-valued `query` verbatim (`round.rs:96-99`) and `run_resolved` sets `interactive = query.is_object()` → `task_loop = false`, sending the normalized value straight to `RoundExecutorHandle::execute` → `ReActAgent::invoke` (`mod.rs:710-720`).
- Accepted resume shape (kernel `InteractiveInput`): `{"query": {"interrupt_answers": {"<interrupt_id>": <answer>}, "user_inputs": {"<tool_call_id>": <answer>}, "raw_inputs": <any>}}`; `interrupt_id`/`answers`/`resume` keys are not recognized anywhere (top-level unknown keys become `extra`, unknown fields inside the object are ignored by the defaulted deserializer).
- Resume requires the same `Arc<dyn Session>` instance: the pause persists interruption state under session key `__react_agent_interruption__` (cleared before replay), no checkpointer is involved, and `invoke(inputs, None)` cannot resume because `resolve_session` creates a fresh `AgentSession`; an object `query` with no pending interruption fails with `Error::validation("interactive input requires a pending interruption to resume")`.
- Permission HITL: the builder registers `PermissionInterruptRail` at priority 90 whenever `config.permissions` is enabled (`builder.rs:425-429`) with the `PermissionHost` from the builder (default `NoopPermissionHost`, whose confirmation default is `ConfirmationOutcome::Interrupt`), so a permission `Ask` pauses with no host fake; resume answers are keyed by tool-call id (the answered call must carry `ToolCall.id`) and re-run `before_tool_call`.
- `ask_user` is always mounted (`ToolRegistry` default set) but returns `success=false` unless `DeepAgentBuilder::user_asker` supplied a `UserAsker`; on success the asker's payload is dropped and the tool returns `data: {}`, so no interrupt is produced by `ask_user` itself.

## Notes for Agents
- `DeepAgent` is built by `DeepAgentBuilder::build()`; the `DeepAgent::new(card) + configure(config)` path defers wiring to the first `ensure_initialized` (flags `wired`/`initialized` keep it idempotent). `configure` never re-mounts tools: it validates the config, rebuilds the prompt, re-applies the inner `ReActAgentConfig`, the tool retry budget and the permission policy, and installs the config last, so a rejected config changes nothing.
- `invoke`/`stream` reset a cancelled `CancellationToken` at the start of a new invocation, so an agent is reusable after `abort()`/`stop()`; `stop()` (not `abort()`) is what makes `phase()` stay `Terminated` and `start()` return `Error::validation("interaction_terminated")`.
- `resolve_deep_agent_parts` appends default rails (security, skills, subagent, goal) first and caller rails last, suppressing a default whose `name()` a caller rail already uses (Python appends caller rails first; registration is priority-sorted, so only equal-priority ties differ — documented deviation); `DeepAgentBuilder::build` adds the same goal rail for a mounted `get_current_goal`/`submit_goal_report` card when the parts did not, so each default is registered once.
- `create_deep_agent`'s boolean keywords (`enable_task_loop`, `restrict_to_work_dir`) overwrite the base config unconditionally; empty lists and `None` keep the base value.
- `wire_subagents` creates the runtime with an empty parent session id (`""`); the concrete session id arrives per spawn through `SubAgentFactory::create(config, session_id)`.
- `DeepAgentBuilder::build` registers the default `SubagentRail` with a `RuntimeSubAgentSpawner` over that runtime (`limit = quota.max_concurrent_running`) and keeps the handle in `DeepAgent::subagent_spawner`; a caller rail named `subagent` suppresses the default (and the accessor reports `None`), so a caller keeps its own seam. `resolve_deep_agent_parts` has no runtime and still registers a seam-less `SubagentRail`.
- Nested `DeepAgent`s built by `DeepAgentSubAgentFactory` run a sub-worktree at `<workspace>/sub-agents/<session_id>` and never mount subagent tools again (depth 1).
- The `pub use` block in `../lib.rs` re-exports the primary items flat from the crate root, so `openjiuwen_harness::DeepAgent` and `openjiuwen_harness::agent::DeepAgent` are the same type; module paths stay canonical and are what the tests use.
- Rail events reach the caller through two independent channels: a streaming caller sees them as `__interaction__` frames ordered with the inner agent's frames, and `drain_rail_events()` returns the retained copy without emptying the stream (and vice versa).
- The `DeepAgent` fields (`prompt`, `queues`, `tool_cards`, `plan_mode`, `inner`, `wired`) are module-private: the in-module `tests.rs` reads them directly, but integration tests under `tests/` must assert through `config()`, `rails().names()`, `phase()`, `load_state()` and the `ScriptedModel` call log instead.
- `save_state`/`load_state`/`clear_state` operate on `last_session`, so they return `Error::validation("no session bound to this DeepAgent")` until an `invoke`/`stream` has run with either a supplied session or a resolvable `None` session.
- Public construction paths: `DeepAgent::new` returns `Self` (not `Arc`), `DeepAgentBuilder::build` and `create_deep_agent` return `Result<Arc<DeepAgent>>`; there is no builder setter for a session (per-invocation argument) or for prompts (prompt text derives from `DeepAgentConfig::system_prompt`).
- A resolved model is only reachable through the private `DeepAgent::model: Arc<RwLock<Option<Arc<dyn Model>>>>` (no public accessor); the workspace stays reachable as `DeepAgent::config().workspace`, while a builder `SysOperation` is consumed into the built tool set and not retained.
- The built `SubAgentRuntime` is stored in the private `DeepAgent::subagent_runtime: Arc<RwLock<Option<Arc<SubAgentRuntime>>>>` with no accessor, and `subagent_factory::wire_subagents` is `pub(crate)`, so the runtime itself stays crate-internal; the delegation seam is public instead, through `DeepAgent::subagent_spawner()` (the `RuntimeSubAgentSpawner` the builder registered on the default rail).
- Per-turn insertion points for a host that journals turns or writes its own session record (no in-crate consumer today): `Driver::run_resolved` has the finished `AgentOutput` just before `persist_state`; `Driver::run_task_loop` receives one `DeepAgentState` per round through the state sink and returns the loop output after `run_until_idle`; `RoundExecutorHandle::run_round` sees every round's outcome after `fire_task_iteration(After)`.

## Test Strategy
- Offline, deterministic tests in `./tests.rs` with `openjiuwen_test_support::ScriptedModel` and `tempfile` workspaces: configure + defaults, prompt includes identity/tools/workspace, single-round answer, tool-call round (fake echo tool), max-iteration error mapping, follow-up queue + state persistence, abort outcome, permission denial skips the tool, mode switch, `send_input`/phase transitions, steering injection, prompt rail section merge.
- Rail-event tests use a `QueueRail` that appends events to `ctx.extra` at the selected hooks: both task iterations reach the stream in order (plus the retained buffer), a terminal goal event settles exactly once, an event queued in the kernel-fired `after_invoke` is drained, two rails drain in `extra` key order, and a round with no queued events drains nothing; `rail_events.rs` unit tests cover the channel conventions, undecodable entries, unrelated `extra` survival, the bounded buffer and the frame forwarding.
