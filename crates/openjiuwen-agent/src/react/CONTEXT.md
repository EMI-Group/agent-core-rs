# react/

## Intent

The ReAct agent: configuration, the model → tools → observation loop, and the streaming model step.
Ports Python `core/single_agent/agents/react_agent.py` (`ReActAgent`, `ReActAgentConfig`, `_inner_invoke`, `_railed_model_call`, `_finish_max_iterations`) without the legacy controller stack.

## API Surface

- `mod.rs` — `ReActAgent` (card + interior-mutable config/model/abilities/rails/prompt builder/context engine/callback framework/steering queue/exposure policy/MCP allowlist/client tools/resilience/final check/KV-cache hook), `ReActAgent::configure/set_model/model/add_tool/add_tools/remove_tool/tools/register_rail/unregister_rail/rails/prompt_builder/context_engine`, the wiring setters `set_callback_framework/callbacks/register_callback`, `steering/steer`, `set_tool_exposure_policy/tool_exposure_policy`, `set_mcp_tool_allowlist/mcp_tool_allowlist`, `set_client_tools/client_tools`, `set_tool_resilience/tool_resilience`, `set_final_request_check/final_request_check`, `set_kv_cache_hook/kv_cache_hook/enable_kv_cache/clear_kv_cache`, the external memory bridge `set_memory_provider/memory_provider/clear_memory_provider/end_memory_session`, and `impl Agent`; defaults are empty callbacks/steering, allow-all exposure, no MCP restriction, an empty client registry, a default (single-attempt) resilience policy, no final check, no KV-cache hook, and no memory provider, so a caller that configures nothing gets the pre-seam loop; the usage seam is `set_usage_analyzer/usage_analyzer`, `set_context_recorder/context_recorder`, `usage_telemetry`, `last_usage`, `drain_usage_events`, and `async fn usage_report(&self, &Arc<dyn Session>, Option<u64>)`, all defaulting to no analyzer/no recorder and an empty telemetry buffer, so the pre-seam loop is unchanged.
- `Agent::invoke` parses the payload, resolves the session (`run::resolve_session`), runs the loop, and finishes an owned session; `Agent::stream` snapshots the agent, spawns the loop, and forwards frames through an unbounded channel (one terminal `answer` frame, or one terminal `Err` for invalid input, an unconfigured model, or cancellation).
- `config.rs` — `ReActAgentConfig` with Python field names/defaults plus `MaxIterationsPolicy` (`Error | FinalAnswer | ReturnObservations`, wire `error|final_answer|return_observations`).
- `agent_loop/mod.rs` — `AgentRuntime::snapshot(&ReActAgent)`, `run(agent, .., owned)`, `run_with(&AgentRuntime, .., owned)`, `run_inner(..)`, plus the `UsageCall { runtime, session, publisher, iteration, request, context, window }` reporter; the snapshot also carries the callback framework, steering queue, policies, the optional external memory provider, the optional KV-cache hook, the shared `Arc<UsageTelemetry>`, and the precomputed model-facing projection (`visible_tool_info`, `visible_cards`); `agent_loop/tests.rs` holds the module's unit tests.
- `agent_loop/kv_cache.rs` — the loop's only cache touch point: `prepare(&AgentRuntime, &Arc<dyn Session>, &[BaseMessage], &ModelRequestConfig) -> Option<KvCacheCall>` (identity from `session.id()`/the request model name/`visible_cards`, then `hook.prepare`, `hook.begin_inference`, `hook.affinity`) and `finish(Option<KvCacheCall>, succeeded, Option<u64>)` (`hook.end_inference` plus `hook.note_usage` on success); `None` when the run has no hook, and every `Err` is logged at `tracing::debug!`.
- `model_step.rs` — a single model call: `call_model` (non-streaming, used only by the tool-free `FinalAnswer` finalization) and `call_model_streaming` driving `Model::stream` through a `StreamAccumulator`, emitting `llm_reasoning`/`llm_output`/`llm_usage` frames through `DeltaSink`, and building `ModelReply { message, finish_reason, usage, reasoning_present }`.
- `resume.rs` — `resume_or_seed(runtime, input, session, publisher, tool_options, ctx, context)` (with `ResumeOutcome { Start { start, original_query, observations }, Paused(output) }` and `seed_auto_confirm`) seeds a fresh turn or replays a persisted `InterruptionState`; `replay_interrupted(state, interactive, tools, options, resilience, client_tools)` replays interrupted tool calls: a `ClientTool` request (or a registered client-tool name) is completed through `ClientToolRegistry::invoke` (handler error → failed result), approvals re-execute through `execute_calls_with` with the resilience policy, rejections carry `reject_feedback`, ask-user answers become the result text, and unmatched requests are returned for re-pausing.
- `pause.rs` — `pause_output(..)` stores the pending requests under their tool-call id, saves `InterruptionState`, publishes and mirrors the `__interaction__` frames, and returns the `result_type: "interrupt"` output.
- `hooks.rs` — callback firing (`invoke_start/step_start/step_end/tool_call_start/tool_call_end/invoke_end`), `drain_steering` (fires `RailRegistry::fire_steering_drain` only when the backlog is non-empty, caps the batch through `RailContext::steering_limit`, and propagates a rail error), and `check_final_request` with `FinalCheckOutcome { Allow, Reject { reason, inject }, Finish }`.
- `frames.rs` — `context_usage(publisher, session, iteration, &PreparedContext)`, `context_usage_post_call(publisher, session, iteration, &Usage, &ContextUsageSnapshot, WindowSummary)`, the `WindowSummary { overflow, window_size }` copy (`WindowSummary::of(&PreparedContext)`) a post-call frame needs after the prepared value was consumed, and `llm_route(publisher, session, &ModelRequestConfig, route, reason)`, all emitted through `DeltaSink` so the stream and the session mirror see them.
- `exposure.rs` — `visible_tools(tool_info, cards, &ToolExposurePolicy, &McpToolAllowlist) -> (Vec<Value>, Vec<ToolCard>)` (one aligned keep-mask) and `is_client_tool(registry, cards, name)`.
- `wiring/` — `#[cfg(test)]` behaviour suites for the loop wiring (`callbacks`, `steering`, `policy`, `client_tools`, `final_check`).
- `prompt.rs` — `build_identity(config, input, extra_fields)` renders the system-role template and `build_system`/`build_system_with_block` wrap it in one system message (the `_with_block` form appends the external memory provider block after the rendered identity); `extra_fields` (`ctx.extra["memory_variables"]`) is merged last, so its string values override same-named input fields and its non-string values are ignored.

## Loop Semantics

- `AgentRuntime` is a synchronous owned snapshot (card id/name, config, model, request config, rails, context engine, full tool map, callback framework, steering queue handle, exposure policy, MCP allowlist, client-tool registry, resilience policy, optional final check, and the projected `visible_tool_info`/`visible_cards`); no `parking_lot` guard is ever held across an `.await`.
- `run_with` opens one root span (`InvokeType::Chain`), builds one `RailContext` for the run, and always finalizes: `AfterInvoke` rails (errors logged), `ContextEngine::save_contexts`, the terminal `answer` frame on success, the external memory provider's `on_session_end` (only when the run owns its session and the output is not an interrupt pause; failures are logged), and the span status; a failing run leaves the terminal frame to the streaming caller so the stream never carries two terminal frames.
- The run's text turns (the user query and every assistant reply, in order) accumulate in `run_inner` and are handed to `memory_provider::finalize_session`, which filters blank turns and calls `MemoryProvider::on_session_end` best-effort; `run`/`run_with` take an `owned` flag that `Agent::invoke`/`Agent::stream` set from `AgentRun::is_owned`.
- `run_inner` creates the context (`"main"`), fires `BeforeInvoke`, then either replays a persisted `InterruptionState` (clearing it, seeding `_resume_interrupt_answers` into `ctx.extra`, observing one tool message per replayed result, and starting at `state.iteration + 1`) or observes the user query and starts at `1`; an interactive payload with no pending interruption is `Error::Validation`.
- Auto-confirm is seeded from the session's `__interrupt_auto_confirm__` on every invoke — the fresh branch seeds it before observing the query, the resumed branch before replaying.
- Replay happens without a model call; requests the caller did not answer re-pause the run with only the remaining requests, reusing their `interrupt_id`s.
- The effective limit is `max_iterations.max(1)` lowered by `_host_max_iterations` and `max_iterations_hard_limit`; each iteration prepares the window (`ContextEngine::prepare` with the rendered system prompt and tool schemas), fires `BeforeModelCall`, streams the model call (at most two attempts when a rail requests a retry after `OnModelException`), fires `AfterModelCall`, and observes the assistant message.
- Both system-prompt builds (the per-iteration one and the `FinalAnswer` finalization one) call `system_message(runtime, input, ctx)` — `build_system_with_block` over `memory_render_fields(ctx)` plus `memory_provider::injected_prompt_block(ctx)` — so the `BeforeInvoke` rails' `ctx.extra["memory_variables"]` (`sys_memory_variables`, `sys_long_term_memory`) render, and the external memory provider's `system_prompt_block` is appended to the identity section, from the first iteration onward; `extra` survives `reset_ctx`.
- No tool calls: `model_continue` keeps iterating, empty text retries once after a notice (`_openjiuwen_message_source_kind = "empty_response"`) and then yields `ResultType::Error` with `模型未返回有效内容（空响应），请重试或检查上下文。`, and non-empty text yields the answer with finish reason, reasoning flag, iteration count, and observations.
- Tool calls: `BeforeToolCall` fires for every call in model order and each call's requests are drained immediately (force-finish, interrupt requests, and `skip_tool` are honoured); a `skip_tool` result is substituted without executing, so `BeforeToolCall` is the only hook that can skip a call.
- When any call of the turn recorded a request, no tool of that turn runs and the run pauses once with all requests collected so far; otherwise the queued non-client calls run in one `execute_calls_with` batch, then `AfterToolCall` fires per result in model order, each tool message is observed (`ToolCallResult::message()`, which is a parts message when the result carries multimodal parts), and observations are recorded in model order with the result's `parts` copied onto `Observation::parts` (cleared when a rail substitutes the text via `skip_tool`).
- Termination: exceeding `max_total_tokens` yields `termination_reason = "token_budget"`; loop exhaustion yields `termination_reason = "max_iterations"`, `truncated_by_max_iterations = true`, and applies `on_max_iterations` (`FinalAnswer` makes one tool-free `call_model` and falls back to `finalization_error`).
- A pause saves `InterruptionState` (requests keyed by tool-call id, answers, assistant message, iteration, original query) and returns `AgentOutput::interrupt` with `__interaction__` frames delivered to the publisher and mirrored into the session.
- `BeforeInvoke`-time `force_finish` is returned untouched; later force-finishes get `iterations_used` and observations attached.
- Every iteration starts by draining the steering queue into the window (`ContextEngine::observe` per message, rendered by `SteeringMessage::to_message`), so a message pushed before the run reaches the first request and one pushed mid-run reaches the next iteration's request; the drain fires `AgentRail::before_steering_drain` through `RailRegistry::fire_steering_drain` only when the backlog is non-empty, reports the queue length in `RailContext::steering_pending`, honours a rail's `RailContext::steering_limit` cap (the whole backlog when untouched), restores both fields to `0`/`None` afterwards, and propagates a rail error to abort the run before anything is drained.
- The steering hook is method-dispatched rather than a `RailEvent` variant, so `ctx.event` keeps reporting the previous firing point while it runs; a rail-capped batch leaves the surplus queued in order for the next iteration or the next run (documented divergence: Python's loop keeps iterating while steering is pending after a tool-free answer, while this port returns the answer and leaves the surplus queued).
- Callbacks fire from `run_inner`: `InvokeStart` once after the effective limit is resolved (original query, resolved limit), `StepStart` before each model call (the messages actually sent, the model-visible cards), `StepEnd` after the reply (text, tool-call count, usage, finish reason), `ToolCallStart` per call that will produce a result (queued calls in model order before the batch, rail-skipped calls at substitution), `ToolCallEnd` in the final per-result loop with the final result (success, failure, or rail-skipped), and `InvokeEnd` unconditionally in `run_with` for both successful and failed runs. A callback error is logged with `tracing::warn!` and never aborts the run; the payload is not built when no callback subscribed.
- The model sees only the projected tools (`ToolExposurePolicy` then `McpToolAllowlist`, precomputed in the snapshot); execution always uses the full tool map, so a hidden tool is still callable through other paths but never advertised. MCP scoping reads `ToolCard.metadata` (`server_name`/`server_id`/`mcp_server`, as `load_mcp_tools` writes) and strips an optional `mcp_<server>_` prefix from the tool name.
- A call to a client tool (registered in `ClientToolRegistry` or carried by a card with `execution == ToolExecution::Client`) is never executed locally: the turn pauses once with an `InterruptKind::ClientTool` request (message "Please run this tool and return its result"), and a resume answer is routed through `ClientToolRegistry::invoke(&call, &answer)` — the handler value (string verbatim, else JSON text) becomes the tool result and a handler error becomes a failed result.
- Tool execution applies the per-tool resilience budget (`ToolResiliencePolicy::for_tool`): the per-call timeout overrides `ToolExecutionOptions::timeout`, tool/timeout failures retry up to `attempts()` with `backoff_for(attempt)`, and `Cancelled`/`Validation` failures are never retried; resume replay uses the same helper.
- A configured `FinalRequestCheck` runs before returning a no-tool-call answer: `Allow` keeps today's behavior, `Reject { inject }` observes `inject` (else the reason) as a user message and iterates while the budget remains (a rejection at the limit falls through), and `Finish(output)` returns that output with progress fields filled; no check configured leaves the empty-response retry untouched.
- Frame emission: a pre-call `context.usage` after every successful `prepare` with `{iteration, phase: "pre_call", message_count, tool_count, token_count, overflow, window_size, usage, result_type}`, where `usage` is `prepared.usage` — the engine's measured snapshot, `null` when no analyzer is installed; a post-call `context.usage` after every successful model call (the streamed iteration call and the `FinalAnswer` finalization call alike) with `{iteration, phase: "post_call", input_tokens, output_tokens, total_tokens, tokens, overflow, window_size, usage, result_type}`, where `tokens` is the snapshot's reconciled window total; `llm_route` with `{route: "backup", model: <request model name>, reason: "model_override", result_type}` before a model call whose resolved model is not the primary one (rail `model_override`, e.g. `ModelBackupRail`, including a retry after `OnModelException`); the primary model emits no route frame.
- Usage reporting: after a successful model call the loop records the provider's report through `ContextEngine::record_provider_usage` under `usage::cache_scope_key(session.id(), model.provider(), &request)` and the deterministic `usage::request_id(session.id(), iteration)` (`"<session>#<iteration>"`, so a retried call updates its entry instead of double counting), then builds `ContextEngine::usage_snapshot(&context, Some(usage.input_tokens))` and stamps the result `phase = "post_call"` with that request id (the engine measures a window, so its own snapshot is always `pre_call` and carries no id). A produced snapshot is pushed into `AgentRuntime::usage_telemetry` and published as the post-call frame; both steps are best effort — a `record_provider_usage` error (blank id) and a missing analyzer (`Error::Config`) are logged at `tracing::debug!` and never change the run's outcome (no frame is emitted without a snapshot).

## Constraints

- The loop never constructs tools or models itself: tools come from the snapshot, the model from `ReActAgent::model()`.
- Rails are fired through `rails::RailRegistry`; every firing point resets the event-specific fields (`reset_ctx`) while `extra`/`session`/`agent_id`/`input`/`iteration` survive.
- Model calls use `ContextEngine::prepare` for the window; assistant/tool messages are appended with `ContextEngine::observe`.
- The engine is rebuilt by `ReActAgent::configure` from `ReActAgentConfig::context_engine_config`, and by `set_usage_analyzer`/`set_context_recorder`; no setter or constructor accepts a prebuilt `ContextEngine`, so a host customises the window/processor pipeline only through `ReActAgentConfig::configure_context_engine` before `configure`.
- Only `create_context`/`prepare`/`observe`/`save_contexts` are called; `compress`, `recover_from_model_exception`, and `load_contexts` are never invoked, so compression is pipeline-driven inside `prepare`. Usage measurement is engine-side too: the loop only calls `record_provider_usage` and `usage_snapshot` on the context it already owns.
- The engine is never handed a model (`create_context`, never `create_context_with` with `ContextOptions.model`), so a `ProcessorConfig::Summarization` in `context_engine_config` fails every run at context creation with `Error::Config` ("the summarization processor requires a model, but none is configured"); model-optional compressors run without one.
- `stream` always runs the loop in a spawned task and mirrors frames into the session; `invoke` passes no publisher.
- Files ≤1000 lines: loop orchestration (`agent_loop/mod.rs`), model-call mechanics (`model_step.rs`), loop hooks (`hooks.rs`), frame emission (`frames.rs`), exposure projection (`exposure.rs`), pause persistence (`pause.rs`), and resume replay/seeding (`resume.rs`) stay in separate files.
- Callback failures are advisory: every firing point logs with `tracing::warn!` and continues, so a broken observer never changes the run's outcome; nothing is built when `CallbackFramework::has_hooks` is false.
- Steering is rail-visible through the opt-in `AgentRail::before_steering_drain` method, not a `RailEvent`: `RailEvent` stays nine variants because `openjiuwen-harness` matches it exhaustively, so `drain_steering` runs before `prepare` and dispatches that one hook through `RailRegistry::fire_steering_drain` while `RailRegistry::fire` stays event-only.
- The projected tool list is computed once in the snapshot and is the only tool projection the loop uses; the full `tools` map is reserved for execution and resume replay.
- KV-cache affinity is best effort and never changes a run's outcome: each model call prepares and records its own scope, and a hook error is logged at `tracing::debug!`; the hook comes from the snapshot, so installing one affects later invocations only, and `KVCacheRuntimeConfig::default()` (affinity disabled) installs an inert hook.
- A retried model call re-runs `prepare`/`begin_inference` per attempt, so no admission lease outlives the attempt that took it; the `FinalAnswer` finalization call is wrapped exactly like an iteration call.

## Test Strategy

- Unit tests beside the modules: `agent_loop::tests` (tool call → answer, empty-response retry, iteration limit, `FinalAnswer` policy, confirm pause/resume, ask-user answer, memory variables reaching every model call, `request_for`, `reset_ctx`, `with_progress`), `model_step::tests` (non-streaming reply, provider error passthrough, streaming content/reasoning/usage frames and their index sequence), `exposure::tests` (allow/deny masks, MCP scoping and prefix stripping, client-tool detection), `frames::tests` (both payload shapes and their stream/mirror delivery), `hooks::tests` (steering rendering, final-check mapping, progress fields), `resume::tests`, `mod.rs` (input/model errors, invoke answer, streaming frames, every wiring setter and its default), `prompt.rs` (field rendering, memory-variable precedence, literal unknown placeholders), and `config.rs`, all on `ScriptedModel`.
- `wiring/` (22 `#[cfg(test)]` tests) covers the seam behaviour at loop level: callbacks (six-event order and payloads, `InvokeEnd` on the error path, a panicking callback is logged not fatal, no-hook short circuit), steering (a message pushed before the run reaches the second request, mid-run push reaches the next iteration, empty queue leaves requests untouched, the drain hook firing once with the backlog size, a rail capping the batch and leaving the surplus queued, the whole backlog landing in the first request without a rail, a rail error aborting the run before the model is called, no firing on an empty queue, and the `(0, None)` field reset at the next firing point), policy (exposure hides a tool from the request while an allowed tool still executes, MCP allowlist scoping, flaky-tool retry then success, retry budget exhaustion, `Cancelled` not retried), client tools (pause shape and resume-through-handler, handler error as failed result), final check (`Reject` injection continues to an answer, `Finish` returns the custom output, `DefaultFinalRequestCheck` rejects an empty answer).
- `../../tests/react_agent.rs` covers the loop end to end: no-tool answer, single/parallel/failing tools, the three max-iteration policies, empty-response retry, prompt rendering, and input/config errors.
- `../../tests/streaming.rs` covers frame assembly plus session mirroring, and `../../tests/interrupt.rs` covers the pause/resume flows end to end.
- `../../tests/memory_provider.rs` covers the external memory provider bridge end to end (prompt block and prefetch in the model window, mounted tool schemas and dispatch, turn write-back, owned-session `on_session_end`, failure tolerance, and `clear_memory_provider`); `../memory_provider/tests.rs` holds the rail/tool unit tests.
- `../../tests/kv_cache_seam.rs` (6) covers the KV-cache seam end to end: `enable_kv_cache` with the default config installs an inert hook (nothing recorded), enabled affinity records the request prefix with the provider's input tokens (the runtime's own `lookup` hits), a hook with an action runtime prefetches and releases its lease without changing the answer, `Redis`/`Distributed` return `Error::Unsupported` naming the backend while the installed hook survives, a run without a hook is unchanged, and the promoted controller/kv-cache facade types are reachable from the crate root.

- `./config.rs` → configuration type and iteration policy
- `./agent_loop/` → runtime snapshot and control flow (`agent_loop/CONTEXT.md`)

- `./model_step.rs` → model invocation and stream accumulation
- `./hooks.rs` → callback firing, steering drain plus the `before_steering_drain` hook, final-request check
- `./frames.rs` → pre-call/post-call `context.usage` and `llm_route` frame payloads
- `./exposure.rs` → tool-exposure projection and client-tool detection
- `./pause.rs` → intercepted-turn persistence and `__interaction__` rendering
- `./resume.rs` → interrupt replay and fresh/resumed turn seeding

- `./prompt.rs` → system prompt assembly
- `../usage/` → the usage telemetry seam over `openjiuwen-context` (`usage/CONTEXT.md`)
