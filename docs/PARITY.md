# Parity Matrix

Reference: openJiuwen Python SDK v0.1.20 (read-only foreign repo `/home/bill/Source/agent-core`).
The parity target is the Python package's public surface: module paths, wire formats, persisted JSON, tool names/schemas, permission outcomes, and observable loop behavior.
Rust internals are idiomatic (tokio, serde, traits, thiserror) rather than a transliteration, so internals are not compared field by field.

## Status Legend

- **Implemented** — the targeted Python public surface is ported, exported, and covered by tests.
- **Subset** — a coherent core is ported and usable while a named remainder is deferred (see §Deferred Features).
- **Stub** — typed entry points exist and return `Error::Unsupported`; it applies to areas inside a crate, never to a crate as a whole.
- **Deferred** — not ported at all, with no Rust crate and no empty seam in its place; like `Stub` it applies only to areas.

## Wire/Behavior Compatibility

### Models and streaming

- OpenAI-compatible vendors (`openai`, `pangu`, `qwen`, `deepseek`, and aliases) resolve to one chat-completions client selected by `ModelClientConfig::provider`/`api_base`; `anthropic` is a distinct Messages transport and `openai_account` selects the Responses transport through `ApiMode::Responses`.
- Requests preserve the OpenAI wire format for messages, tool calls, `tool_choice`, `temperature`, `top_p`, `max_tokens`, `stop` and streaming `stream=true`.
- `ModelRequestConfig::{purpose, metadata}` are client-side routing and telemetry hints: no transport reads them and no protocol builder writes them to a request body, and the legacy `extra` spellings (`request_purpose`, `purpose`, `metadata`, `context_operation_id`) are stripped by `extra_without_internal_keys`.
- Anthropic keeps the three automatic `cache_control` anchors and hoisted-or-inline mid-conversation `system` turns; per-message caller breakpoints and selectable caching modes are absent, and non-streaming thinking blocks are dropped.
- Responses expose `ChatResponse`/`Choice`/`Usage` and a `StreamChunk` stream (`Delta`, `Usage`, `Done`); `StreamChunk::Delta` additionally carries `finish_reason`, an additive field, and the SSE decoder keeps `[DONE]`, keep-alive comments and unknown event types lossless.
- Parallel tool calls and argument deltas are accumulated by `ToolCallAccumulator`; a mid-stream provider failure surfaces as the stream's `Err` item.
- Retries and timeouts live in the shared HTTP client (`OPENJIUWEN_LLM_TIMEOUT_SECS`); a non-2xx response is returned normally unless the caller requests `error_for_status()`.

### Cards, tools, and schemas

- Every `*Card` is a serde struct with Python field names and `#[serde(default)]`; unknown fields are tolerated and `None` fields are skipped on serialize.
- Cards implement `openjiuwen_common::card::Card` and derive `schemars::JsonSchema`, so JSON Schema is generated rather than hand-written.
- `ToolCard` is flat (`id`, `name`, `description`, `input_params`, `properties`, policy flags) with `openai_tool()`/`flat_tool_info()`; `ToolInfo::flat()`/`from_flat()` round-trips Python's flat literal and `ToolInfo::openai()` emits the function-calling shape.
- `FunctionTool` handlers are async-only; Python sync handlers and generator-based tool streams are not reproduced (a blocking handler must use `spawn_blocking`).
- MCP tool names and JSON schemas are preserved through `McpTool`; streamable HTTP replays `Mcp-Session-Id` and holds the server-initiated GET stream, and resource listing/reading is implemented for transports that support it.

### Sessions and checkpoints

- State is JSON, keyed by `session_id`, with a global lane and component-namespaced lanes; dumps keep Python field names.
- `AgentSession` is the in-memory session implementation; there is no separate `InMemorySession` type in the Rust API.
- Checkpointing is the `Checkpointer` trait: in-memory, filesystem/JSON, SQLite (`sqlite` feature), and a Redis RESP2 checkpointer that is always compiled; disk-backed product sessions are `DiskSessionStore` records with local `SessionHistory` versions.
- Python pickle checkpoint payloads cannot be read, and a resumed trace continues from the checkpointed baseline.
- Human-in-the-loop pauses are `AgentOutput { result_type: Interrupt, ... }` values plus persisted `InterruptionState`, and resume is a normal invoke with an `InteractiveInput` in the query slot.
- Sessions write streaming frames as `StreamItem` values; agent `AgentChunk` frames map onto them and remain the public streaming contract.

### Workflow data flow

- `${node.field}` references are compiled once per node into a schema template and resolved against run state through a `StateView` (no per-node state clone); a missing path resolves to `null` instead of failing, and a non-numeric field segment applied to an array of objects projects over its elements.
- `outputs_schema` resolves against workflow state plus the node id and an `output` key (`${<id>.field}` / `${output.field}`); there is no `self` shorthand or bare `${field}`.
- `wait_for_all=false` with at least two inbound sources compiles to first-arrival dynamic edges (the node re-fires and unproduced keys resolve to `null`), while CNF barriers remain for single-source nodes, declared conditional edges only, and `Collect`/`Transform` nodes.
- `HttpResponseFormat::Buffer` decodes into a base64 string (and `binary_data` is base64-decoded on the way in) because JSON has no bytes type; Python returns `bytes`.
- Builder methods never return `Err`; problems are recorded and reported by `build`/`invoke`/`stream`/`to_mermaid`.

### Documented deviations

- `AgentSession` replaces Python's `InMemorySession`; `create_agent_session`/`AgentSession::with_options` are the constructors.
- `LlmAgent::new(LlmAgentConfig)` plus `set_prompt_template` are the configuration entry points where Python exposes `LLMAgent.configure`.
- A denied tool call is not an error: the observation starts with `[PERMISSION_DENIED]` (`DENIED_PREFIX`), `result_type` stays `Answer`, and the loop continues.
- CLI JSON shapes are `{answer, result_type, usage, session_id}` and a `stream-json` line per chunk plus a terminal `{"type":"result", ...}` line; Python emits a different `{result, chunks, model}` object and no terminal line.
- The CLI prints plain text by default and enables ANSI colour only on a TTY without `--no-color`/`NO_COLOR`; a persistent `~/.openjiuwen_history` with optional replay replaces Python's history handling.
- `TeamAgentSpec`'s `SpecBuild` is `#[async_trait]` and `build_with(&self)` does not mutate the spec (Python's `build()` fills `language` in place).
- Teammate worktree names use a 10-hex FNV-1a digest instead of `sha256(...)[:10]`, and member state lives under `<base>/<team>/sessions/<sid>/members/<member>`.
- `openjiuwen-harness-providers::create_harness` cannot receive an injected `Model`; offline tests construct `NativeHarness::new(agent, options)` directly.
- Errors are one `Error` enum plus `ErrorKind`, with `"<kind>: <message>"` display; Python's numeric `StatusCode` and exception class tree are not reproduced.
- Token counting resolves a tokenizer spec/registry, then a model→encoding table (`cl100k_base`/`o200k_base`), then tiktoken's model lookup, and finally a character-ratio approximation, so counts can differ from Python for uncatalogued models.
- Ordering is deterministic where Python used sets or dict iteration (sorted subscribers, ordered tool batches, sorted registry listings).

### Gaps that are not typed seams

- `openjiuwen-harness` records one `ExecutionRecorder` entry per turn rather than per model or tool call, its memory search is keyword-only (no embedding or hybrid index), and resume stays host-driven: a host builds the `ResumePlan` and seeds a `ResumedTurn`/`seed_history` itself.
- `openjiuwen-foundation`'s `ModelRequestConfig::{purpose, metadata}` are decoded and validated but never serialized to a provider.
- `openjiuwen-workflow`'s `HttpResponseFormat::Buffer` returns a base64 string rather than bytes.
- `openjiuwen-multiagent` accepts an inbound transport but leaves the worker loop to the caller.
- `openjiuwen-agent-teams`' `distributed` feature compiles the messager seams and then rejects them at construction.

## Intentionally Different

- Typed traits and structs replace Python duck typing, decorators, and pydantic validation; cards carry `schemars` schemas instead of runtime validators.
- Streaming is `BoxStream<'static, Result<T>>` built with `async_stream`, not asyncio queues; cancellation is `tokio_util::sync::CancellationToken`.
- Synchronous Python entry points become `async`; there is no `asyncio.run`/`block_on` bridging in library APIs (`dev_tools` builders, `init_model`, `SpecBuild`).
- `Error` is one typed enum with `ErrorKind`; error categories preserve Python names but numeric status codes are gone.
- Registries are typed and instance-scoped (`ModelProviderRegistry`, `ToolRegistry`, `StoreRegistry`, `ResourceMgr`, the harness provider registry) instead of module-level dicts; `Runner::global()` is the one documented process singleton.
- Services are injected as `Arc` values (`LongTermMemory`, `Runner`, sessions, checkpointers); Python's process-global memory singleton and implicit `Runner` wiring are gone.
- serde uses `snake_case` by default and `camelCase` only where an external protocol requires it (A2A, OTel attribute keys); unknown fields are tolerated everywhere.
- One `BaseMessage` struct replaces four role subclasses, and `ToolCard` is flat instead of embedding `CardBase`.
- Structured concurrency replaces asyncio task groups: the task manager registers before polling, tracks abort handles, catches panics, and aborts leftovers on drop.
- `AgentOutput.output` is a string with structured payloads in `data`/`workflow_output` (Python nested dicts are not reproduced).
- Determinism is a design rule: ids are explicit or UUID-based, subscriber/tool/registry ordering is sorted or insertion-ordered, and tests never assert wall-clock values.
- Rust-only additions have no Python counterpart: `multiagent::{routing,inbox}`, the `extensions::observability` package, the context `TokenizerArtifactManager`, the Redis Streams team transport, `harness`'s `mcp_resource_subscription` tool, and `openjiuwen-workflow::render`'s deterministic SVG.

## Verification

- `make verify` — `fmt-check`, `clippy`, `test`, `test-all` and both example builds, in that order; it is the gate, and no count in this document substitutes for it.
- `make test` (`cargo test --workspace --offline --no-fail-fast`) — the default gate over all 30 crates. Two targets fail: `openjiuwen-cli/tests/sessions.rs` (`prune_reports_the_selection_then_deletes_it` and `a_session_in_all_three_stores_is_listed_and_pruned_once` report a source surviving a prune) and `openjiuwen-e2e/tests/runner_hosting.rs::active_spawns_track_each_hosted_child_until_its_own_handle_ends` (the run reports `Cancelled` where the scenario expects `Completed`). Every other target passes.
- `make test-all` — the feature-gated suites: `cargo test -p openjiuwen-e2e --features a2a`, `-p openjiuwen-extensions --features a2a,otel`, `-p openjiuwen-harness --no-default-features`, `-p openjiuwen-agent-teams --no-default-features`, `-p openjiuwen-symphony --features sqlite`, `-p openjiuwen-sysop --features sandbox`, `-p openjiuwen-harness-providers --features vendor`.
- Per-package suites: `cargo test -p openjiuwen-e2e` (the cross-crate scenarios; default features compile the feature-gated cases empty), `-p openjiuwen-e2e --all-features` (every scenario), `-p openjiuwen-examples` (the `src/support/` unit tests, a doctest, and `tests/examples_offline.rs`, which runs every example binary the enabled features compile), and `-p openjiuwen-test-support` (offline, loopback-only, waits bounded at ≤2 s).
- `cargo fmt --all -- --check` and `cargo clippy --workspace --all-targets -- -D warnings` — the style and lint gates (`make fmt-check`, `make clippy`).
- `cargo doc --workspace --no-deps` and the same with `--all-features` — the rustdoc gate; private or feature-gated items are linked as plain code spans instead of widening visibility.
- `cargo build -p openjiuwen-examples --examples` and `cargo build -p openjiuwen-examples --examples --features a2a,mcp` — compile the offline example set and the A2A/MCP-gated one (`make examples`).
- A bare `cargo test` uses the `default-members` list and therefore skips `openjiuwen-e2e`, `openjiuwen-examples` and `openjiuwen-test-support`; use `--workspace` or name those packages explicitly.
- Tests carrying `#[ignore]`: `openjiuwen-sysop/src/sandbox/http.rs::probe_against_live_gateway` (needs a live sandbox gateway, so it only compiles under `--features sandbox`), `openjiuwen-e2e/tests/cli_binary.rs::binary_version_over_the_process_boundary` (the binary belongs to `openjiuwen-cli`; the process-level smoke lives in `openjiuwen-cli/tests/cli_smoke.rs`), and the three stdio protocol children re-executed by their own suites (`openjiuwen-runner/tests/spawn_seam.rs`, `openjiuwen-runner/tests/spawn_subprocess.rs`, `openjiuwen-runner/src/spawn/subprocess_tests.rs`); the remaining ignored runs of the default gate are doctest `ignore` blocks, which `cargo test --list` reports alongside the attributes.
- Nothing in the suite needs the network, credentials or a wall clock: scripted models or the loopback `MockLlmServer`, temp directories, loopback sockets and bounded awaits; `OPENJIUWEN_LIVE` only switches the examples between offline and live.
- `openjiuwen-dev-tools/tests/deferred_surface.rs`, `openjiuwen-symphony/tests/deferred.rs`, `openjiuwen-agent-evolving/tests/rl.rs` and `openjiuwen-sysop/tests/sandbox_stub.rs` assert the `Error::Unsupported` messages of the deferred surfaces rather than merely describing them.
