## Deferred (still unimplemented)
- `openjiuwen-agent` — controller background scheduling/concurrency, task-manager indexes/filters/dependency scheduling, executor pause/cancel, per-conversation `TaskQueue` cancellation, group routing, `agent_reasoner.py`; KV-cache provider prefetch/offload and Redis/distributed backends; operator legacy `LLMCall` wrapper, `MetisContextEvolveOperator::learn`, `SkillExperienceOperator` staging; memory-variable prompt injection; Python-layout prompt files (design/format).
- `openjiuwen-multiagent` — Pulsar transport, poll-based and per-instance Redis delivery, Redis cluster/Sentinel/Streams consumer groups, drunner factories/reply-topic routing/`RemoteAgent`, and an out-of-process team event bus (external service/operational).
- `openjiuwen-runner` — Pulsar/ZeroMQ/A2A transports and reply-topic routing, Python's `python -m` child bootstrap and process pool, OS-process/external-CLI/SSH members, cross-process attach, the org layer, `TeamStreamLogger`/monitor TUI, in-loop `InteractGate`, HITL auth/ACL, monitor persistence/export, callback signature introspection and parallel triggers, resource-manager extras (operational/external service/platform).
- `openjiuwen-sysop` — `aio`/`jiuwenbox`/`yuanrong` sandbox transports, endpoint discovery beyond `LaunchedSandbox`, auth-header/query injection, the streaming wire format, provider/container caches; Big5-HKSCS/CP932 extensions, legacy-encoding writes, whole-buffer auto detection; the macOS `script` wrapper and Windows command classification heuristics (vendor SDK/platform/format).
- `openjiuwen-core` — (none).

## Error::Unsupported surface
- `openjiuwen-agent`: `kv_cache::types::KVCacheBackend::runtime` — the Redis and distributed cache backends have no implementation; only the in-process runtime exists.
- `openjiuwen-agent`: `operator::context_evolve::MetisContextEvolveOperator::learn` — the ML-backed Metis learner is not ported.
- `openjiuwen-multiagent`: `transport::build_transport` with `TransportKind::Pulsar` — no Pulsar client exists in the workspace.
- `openjiuwen-multiagent`: `BaseTeam::new` without a strategy — `invoke`/`stream` have no strategy to delegate to.
- `openjiuwen-runner`: `spawn::UnsupportedSpawner` — the documented default when no spawn backend is installed on a runner.
- `openjiuwen-runner`: `spawn::remote::RemoteProtocol::{Mq, A2a}` — reply-topic distributed transport and A2A remote agents are not ported.
- `openjiuwen-runner`: `mq::create_message_queue` for `MessageQueueKind::{Pulsar, ZeroMq}` — no broker client is compiled into the build.
- `openjiuwen-sysop`: `sandbox::http::HttpSandboxGateway::invoke` — the provider streaming wire format is not ported, so remote calls surface as 199007.
- `openjiuwen-sysop`: `sandbox::provider`/`sandbox::launcher` dispatch — no provider/launcher registered for a `sandbox_type`/`launcher_type`, or the `sandbox` feature disabled, is the only `Unsupported` path; a registered launcher that fails is 199008.
- `openjiuwen-core`: (none).
