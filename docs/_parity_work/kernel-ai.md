## Deferred (still unimplemented)
- `openjiuwen-workflow` — live interleaving of concurrent streaming producers (Python's actor network), PNG rendering plus `WORKFLOW_DRAWABLE` gating, per-run `async` graph mutation, and sub-workflow HITL resume with forwarded seeded answers (format/design).
- `openjiuwen-context` — tokenizer artifact manager and downloads, native `tokenizer.json`/`tiktoken.model` loading, `provider_official` adapters, usage/KV-cache telemetry, provider-specific context policies and OpenRouter window cache, Python's adaptive compressor/summariser strategy selection, `processor/forked/` monkey-patching, rule-based offloader compression and file-based archive dumps, compression state stream frames (ML/research stack, ecosystem).
- `openjiuwen-memory` — real vendor transports/SDKs for AgentArts/Jiuwen/LakeBase/mem0/OpenViking and Python's tool-rail provider surface, per-backend migrators with backup/restore keyspace, AES at-rest codec, distributed KV lock and `scope_user_mapping`, the Milvus-backed graph stack (LLM dedupe, time validity, relation rewiring), lite `sqlite_vec` embeddings and `MEMORY.md` per-fact split, the dreaming orchestrator's idle loop and LLM consolidation, team-memory `TEAM_MEMORY.md` format and bus hooks (vendor SDK, ML/research stack, format/design).
- `openjiuwen-retrieval` — Milvus/Chroma/PGVector/Elasticsearch vector stores, DashScope embeddings and rerankers, LLM image captioner and LLM triple extractor (trait seams only), multimodal embedding models, OCR for scanned PDFs, encrypted PDFs and PDF object streams, cross-reference-table page ordering (external service, ML/research stack, format/design).
- `openjiuwen-security` — `LocalModelBackend` inference runtime (`torch`/`transformers`), moderation transports beyond OpenAI/Azure/Aliyun (DashScope/Google/Bedrock), batched or streaming moderation with multi-result aggregation, the process-global `register_guardrail` helper (owned by `openjiuwen-runner`) (ML/research stack, vendor SDK, operational).

## Error::Unsupported surface
- `openjiuwen-context`: `tokenizers::load_native_tokenizer` — loading a HuggingFace `tokenizers` artifact needs the native `tokenizers` runtime and network downloads.
- `openjiuwen-workflow`: `Component::invoke`/`stream`/`collect` defaults when a component does not declare that ability — the engine only calls declared abilities, and the default names the missing capability.
- `openjiuwen-workflow`: `components::http_request::{prepare_body, apply_authentication}` — multipart bodies and digest/AWS request signing are not implemented.
- `openjiuwen-retrieval`: `Loaders`/`AutoLoader` — unknown file extensions and image-only PDFs; `parsing::zip`/`zlib` — ZIP64, split or encrypted archives, non-stored/deflate methods, preset dictionaries; `parsing::pdf` — `/Encrypt` and compressed object streams; `vector_store::VectorStoreRegistry` — any provider other than `memory`/`in_memory`; `chunking::ChunkerRegistry` — unknown chunker names.
- `openjiuwen-memory`: `external::vendor` — the five vendor providers (`AgentArts`, `Jiuwen`, `LakeBase`, `Mem0`, `OpenViking`) name the missing SDK/transport; `external::registry` — an unregistered provider factory; `engine`/`lite` — `SearchMode::Semantic` without an embedding model; `lite::lock::FileLock` — non-unix targets.
- `openjiuwen-security`: `backends::local::LocalModelBackend::analyze` — no local inference runtime; `backends::api::ApiModelBackend` — no injected `ModerationTransport`.
